# 계정 삭제 요청 · AI 응답 신고 — 운영 처리 절차

> 2026-11-27 작성(Google Play 출시 준비). 접수 경로 코드: core `support-requests.ts` · data `supportRequests.ts` ·
> 앱 `app/settings/account-deletion.tsx`·대화 신고 · 웹 `/account-deletion`.
> ⚠️ 처리 기한·본인 확인 방법·보존 예외는 **법무 확인 대기**다(아래 "확인 필요"). 확인 전에는 이 문서의 기준으로 처리한다.

## 1. 접수 경로 — 둘 다 "비공개 문의"로 들어온다

| 종류 | 문의 제목 | 들어오는 곳 |
|---|---|---|
| 계정 삭제 요청 | `[계정 삭제 요청]` (고정) | 앱 설정 → 계정 → 계정 삭제 요청 · 웹 `/account-deletion` · 막힌 계정 알림의 '계정 삭제 안내' |
| AI 응답 신고 | `[AI 응답 신고] <사유>` | 앱 대화 화면(진행 중 질문 카드 아래) · 앱 대화 기록의 AI 말풍선 |
| 이메일 삭제 요청 | (메일) | 개인정보 보호책임자 이메일 — 앱·웹에 로그인할 수 없는 사람용 |

- 비공개 문의는 **작성자와 사이트 운영자(`users.is_site_admin`)만** 읽는다(RLS). 운영자는 웹 `/inquiries` 에서 제목으로 찾는다.
- 계정 삭제 요청은 처리 대기(`status='waiting'`) 중이면 다시 눌러도 새로 쌓이지 않는다.
- 운영자 조회(읽기 전용 SQL, 대시보드 SQL 편집기):

```sql
select id, title, created_at, status
from public.inquiries
where title = '[계정 삭제 요청]' or title like '[AI 응답 신고]%'
order by created_at desc;
```

## 2. 계정 삭제 요청 처리

**처리 기한**: 요청을 받은 날부터 **10일 이내**(웹 `/account-deletion` 에 공개한 기준 — 개인정보 보호법상 삭제 요구 처리 기한. 법무 확인 대기).

1. **본인 확인**
   - 앱·웹 접수: 로그인한 본인 명의로만 들어오므로 그 자체가 본인 확인이다(문의 `author_id`).
   - 이메일 접수: **보낸 주소 = 가입 이메일**일 때만 진행한다. 다르면 가입 이메일로 확인 메일을 보내 회신을 받는다.
2. **접수 회신**: 문의에 답변(또는 메일)으로 접수 사실과 처리 예정일을 알린다.
3. **사전 확인**(읽기 전용):
   - 기관 관리자(`org_admin`)이고 그 기관의 유일한 관리자이면, 처리 전에 기관에 다른 관리자 지정을 요청한다. 관리자가 없는 기관이 되면 구성원 승인·권한 변경을 할 사람이 없다.
   - 지울 계정을 막는 외래키가 없는지 본다. 사이트 운영자 계정은 문의 답변(`inquiry_replies.author_id`, `restrict`)이 있으면 삭제가 거절된다. 운영자 계정은 이 절차 대상이 아니다.

```sql
-- 계정을 지우면 어떤 행이 함께 지워지거나(cascade) 작성자 표시만 지워지는지(set null)
select conrelid::regclass as tbl, conname, confdeltype
from pg_constraint
where contype = 'f' and confrelid = 'public.users'::regclass
order by confdeltype, tbl;
-- confdeltype: c = 함께 삭제 · n = NULL 로 · r/a = 삭제를 막음(있으면 먼저 처리)
```

4. **삭제 실행**: Supabase 대시보드 → Authentication → Users → 해당 사용자 → **Delete user**.
   `auth.users` 삭제가 `public.users` 로 이어지고, 외래키 규칙대로 처리된다(2026-11-27 마이그레이션 기준):
   - **함께 삭제**: 기관 합류 요청 · 보호자 연결 · 담당 배정 · 알림 · 푸시 토큰 · 본인이 쓴 문의(이 삭제 요청 문의 포함)
   - **작성자 표시만 NULL**: 어르신 프로필·연대기·세션·대화 기록·일지 등 기관 기록, 동의 이력(증빙 보존)
   - **그대로 보존**: 접속·처리 기록 `audit_log`(행위자 id 만 남고 외래키 없음 — 최소 2년 보존 후 파기)
5. **완료 통지**: 삭제 요청 문의도 함께 지워지므로 **가입 이메일로** 완료를 알린다.
6. **처리 기록**: DB 밖 운영 기록(처리 대장)에 접수일·처리일·문의 id·처리자만 남긴다. 이메일·이름은 적지 않는다.

> 보호자 계정도 같은 절차다. 보호자 연결이 함께 지워지므로 공유받던 기록은 더 볼 수 없게 된다.
> 어르신 정보의 삭제(어르신 본인·대리인 요청)는 이 절차가 아니라 기관이 어르신 프로필을 삭제하는 경로다(앱·웹 '담당 어르신 관리').

## 3. AI 응답 신고 처리

Google Play AI 생성 콘텐츠 정책: 앱 안에서 개발자에게 신고할 수 있어야 하고, **신고를 필터링·검수 개선에 쓴다**.

1. **주 1회 이상** 신고 문의를 확인한다(파일럿 중에는 접수 당일).
2. 사유별로 분류한다:
   - `건강·약·안전에 관한 위험한 조언` · `불쾌하거나 부적절한 표현` → **안전 규칙 보완 후보**. core `safety.ts`(출력 검열)·
     프롬프트에서 같은 표현이 왜 통과했는지 확인하고, 재현 테스트를 먼저 만든 뒤 고친다(AGENTS "안전·동의 로직" 검증 순서).
   - `개인정보를 말하거나 물어봄` → 프롬프트·검열 규칙 확인.
   - `사실과 다르거나 엉뚱한 내용` · `기타` → 대화 품질 과제로 모은다.
3. 신고자에게 문의 답변으로 조치 결과를 알린다.
4. 신고 본문에는 AI 발화가 그대로 들어 있다(어르신 이야기 일부가 포함될 수 있다). 처리 후 필요 없는 원문은 문의를 삭제해 남기지 않는다.
