## R002 — 세션 부모와 어르신·기관 소속 일치

파일: `supabase/migrations/20260909000000_session_ownership_integrity.sql`

- sessions → profiles, session_logs/session_analyses → sessions, safety_events → profiles/sessions에 복합 외래키를 추가했다.
- UPDATE 대상에도 기관·담당자 범위를 검사하는 restrictive 정책 4개를 추가했다.
- 보호자 공유 판정은 실제 부모 세션, 분석, 공유, 승인된 보호자 연결의 profile_id/org_id가 모두 일치하고 세션이 ended인 경우만 허용한다.
- 세션 삭제 시 안전 이벤트는 보존하고 session_id만 비운다. 행위자 user_id는 교대·탈퇴와 소속 무결성을 혼동하지 않도록 복합키에 넣지 않는다.
- 적용은 단일 트랜잭션이다. 기존 불일치 자료가 있으면 외래키 검증에서 실패하고 전체 롤백한다. 임의 소속 변경이나 자동 백필은 하지 않는다.

운영 적용 전후에는 아래 별도 읽기 전용 SQL을 사용한다. `supabase/tests/rls_regression.sql`은 격리 테스트 DB의 합성 자료용이며 운영 DB에서 실행하지 않는다.

```sql
select conrelid::regclass as target, conname, convalidated, pg_get_constraintdef(oid)
from pg_constraint
where conname in (
  'profiles_id_org_unique', 'sessions_id_profile_org_unique',
  'sessions_profile_org_fk', 'session_logs_session_profile_org_fk',
  'session_analyses_session_profile_org_fk', 'safety_events_profile_org_fk',
  'safety_events_session_profile_org_fk'
);
select tablename, policyname, permissive, roles, cmd, with_check
from pg_policies
where schemaname = 'public' and policyname in (
  'sessions_update_target_scope', 'session_logs_update_target_scope',
  'session_analyses_update_target_scope', 'safety_events_update_target_scope'
);
select pg_get_functiondef('app.is_session_shared_to_me(uuid)'::regprocedure);
```

기대 결과는 검증된 제약 7개, authenticated UPDATE에 대한 RESTRICTIVE 정책 4개, 마이그레이션과 일치하는 공유 함수다. 배포 시 저장소 버전과 migration history를 함께 관리해야 한다. 이미 생성된 제약에 동일 SQL을 무조건 재실행하지 않는다.

## R003 — 네이티브 마이크 API 연결

`apps/mobile/src/lib/live/mic-adapter.ts`에서 설치된 react-native-live-audio-stream 1.1.1의 init/start/stop/on API와 default export를 사용한다. 구독 해제·중복 시작 차단·시작 실패 후 정리·재시작을 구현했다. 세션 화면에는 시작 실패 안내를 연결했다.

테스트는 설치된 라이브러리의 실제 JavaScript 진입 파일을 실행하고 네이티브 모듈 경계만 대체한다. Java/Kotlin/Objective-C의 실제 마이크 동작을 증명하는 테스트는 아니다.

실기기 확인: 네이티브 모듈이 포함된 개발/배포 빌드에서 권한 허용 후 16kHz mono PCM 수신, 정지 후 이벤트 중단, 재시작, 권한 거부 시 안내를 확인한다. Expo Go만으로 완료 판정하지 않는다.

## R004 — Gemini Live 연결 및 출력 계약

`client.ts`의 임시 토큰 연결 경로를 BidiGenerateContentConstrained/access_token으로 맞추고 setupComplete 이후에만 입력을 허용한다. AUDIO 출력, 전사, 수동 activityStart/activityEnd 설정을 명시했다. 준비·응답 타임아웃과 소켓 종료 시 대기를 해제하며 이전 연결의 늦은 응답이 다음 응답에 섞이지 않도록 차단했다. Blob/ArrayBuffer 프레임도 순서대로 처리한다.

`engine.ts`는 음성용 프롬프트를 사용하며 종료 후 재연결 타이머를 정리한다. `packages/core/src/prompt.ts`는 기본 구조화 응답 계약을 유지하면서 음성 경로의 JSON 출력 강제를 제거한다. live-token 함수는 v1beta 토큰 설정과 no-store 응답을 사용한다.

실연동 확인: 변경한 Edge Function 배포 후 인증된 앱에서 임시 토큰 발급, setupComplete, 음성 입력·확인·음성 응답, 두 번째 턴, 연결 중 종료, 연결 중단 후 재접속을 확인한다. 토큰/키/대화 원문을 검증 보고서에 기록하지 않는다. 원음도 Live 모델에 전송되므로 보정된 텍스트만 모델에 전달된다고 설명해서는 안 된다.
