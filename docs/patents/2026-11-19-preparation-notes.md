## 5 작성 중 발견한 차이와 표현 제한

### 5.1 재생 관찰의 영속 저장

`docs/database.md`는 `save_voice_playback_v1`의 SQL·마이그레이션을 미구현이라고 표시합니다. 현재 저장소 검색에서 RPC 타입·어댑터·가상 RPC 테스트는 확인됐으나 마이그레이션 정의는 확인되지 않았습니다. 중계의 재생 영수증 프로토콜은 실제 구현돼 있으므로 이를 모두 미구현이라고 묶는 것도 부정확합니다.

처리: 본문은 프로토콜 상태 관리와 DB 영속 보존을 구분합니다. 운영에만 존재하는 구현은 이번 작업에서 확인하지 않았으므로 영속 저장 완료를 주장하지 않습니다. 제품 수정은 이번 문서 작업의 범위가 아닙니다.

### 5.2 근거 객체와 최종 일지의 연결

생성 단계에서 근거 객체를 검사하지만 워커가 저장하는 일지 필드는 `mapAnalysisToJournalFields`의 문자열입니다. 검증된 근거가 일지 문장 옆에 표시되거나 생성 원출력·근거 객체 전체가 별도 보존된다고 쓰지 않습니다. 후속 설계로 제안할 경우 현행과 분리해야 합니다.

### 5.3 보호자 자유 문장의 검증

생성 지시는 근거를 요구하는 취지이지만 스키마의 `guardianText` 자체는 문자열입니다. 생성 주장 배열과 동일한 턴 ID·인용 객체 검사를 받지 않습니다. ‘모든 결과 문장에 근거가 강제된다’는 표현을 피하고 적용 대상을 명시했습니다.

### 5.4 과거 문서의 고정 턴 수와 무음 경계

파일럿 계획 일부에는 턴 상한이나 과거 무음 1·2초가 남아 있습니다. 최신 작업 상태는 턴 수 종료 제거와 무음 3초 코드 변경을 기록합니다. 발명 설명에서는 상태·시간 제어 원리를 중심으로 쓰고, 고정 수치를 적을 경우 최신 구현·기기 버전을 구분합니다.

### 5.5 역할과 공개 위임

구조 요약의 ‘공개/철회’와 실제 위임 키는 동일한 단위라고 단정할 수 없습니다. 확정·문장 승인·공개·철회를 별도 작업으로 설명하고 실제 서버 계약을 기준으로 합니다. 요양보호사라는 직무명과 서버의 전체 돌봄팀 역할을 혼동하지 않습니다.

### 5.6 국내 보관과 외부 AI 처리

서울 DB·중계 운영이 외부 AI 처리까지 국내로 한정됨을 뜻하지 않습니다. ‘전 과정 국내 보관·처리’는 확인된 범위를 넘으므로 본문에 쓰지 않았습니다. 비밀값·개인 발화 원문·내부 서비스 식별자는 첨부하지 않습니다.

### 5.7 효과 수치

회의의 18시간→15시간은 예시입니다. 합성 첫 청크 약 1.18초와 워커 접수→DB 저장 약 4.16초는 각각 제한된 측정이며 전체 대화 지연·직원 업무시간의 단축 효과가 아닙니다. 본문은 실제 비교 효과 수치를 확정하지 않았습니다.

### 5.8 사용자 지시에 따른 시험과 화면의 범위

2026-11-19 사용자는 요양원 시험이 도중 중단됐으므로 검토본에서 제외하도록 지시했습니다. 외부 본문에서는 현장 참여자·사용 결과·후기 및 이를 확인해 넣겠다는 예고를 제거했습니다. 이 사실은 이번 검토본의 포함 범위이며 과거 시험·기술 점검 문서를 삭제하거나 무효화하는 지시가 아닙니다.

화면은 첨부 방식만 보류된 상태입니다. 임의로 설명용 재현 화면을 촬영·추가하지 않고, 방식 결정 후 필요한 범위에서 준비합니다. 미래 구상을 폭넓게 포함한다는 답변도 기존 제품 정책이나 개별 제안의 승인으로 확대하지 않습니다.

### 5.9 전체 입력정보 활용의 현재 구현과 미래 방향

현재 `formatElderFacts`는 기본 프로필과 `chronicle.slice(0, 10)`을 반영합니다. 미래 방향의 ‘기존 정보 모두’는 현재 구현의 설명으로 치환하지 않습니다. Q22 통합 기본안으로 전체 보관과 관련 정보 활용은 확정됐습니다. 특정 검색 알고리즘·저장 구조·성능까지 확정된 것은 아닙니다.

### 5.10 의료진 연계 제외

사용자는 의료진·병원 피드백을 이번에는 제외하도록 정했습니다. 외부 본문의 제외 범위 설명 외에는 미래 확장 표·수신자·검토 요청에서 의료진 연계를 제거했습니다. 응급 신호 안전 처리나 기존 개인화 계획의 비의료 제약을 없애는 변경은 아닙니다.

2. 실제 기록 화면과 설명용 데이터로 재현한 화면을 구분합니다.

6. 화면 준비를 위해 운영 데이터를 쓰거나 운영 설정을 바꾸지 않습니다.

- 다이어그램이 본문의 권한·안전·승인 조건과 일치하는지 확인.
- 화면 첨부 방식 결정 후 첨부와 개인정보 제거를 확인. 보류 상태라면 텍스트·흐름도 위주 전달 가능 여부를 확인.
- 저장소 밖에서도 읽을 수 있도록 내부 상대 링크를 부록 설명·첨부로 전환.
- 요구 파일 형식으로 변환한 경우 도면·표·한글·쪽 나눔을 직접 확인.
- 사용자 검토 후 전달. 수신자에게 발송하려면 별도 명시적 발송 지시 필요.

## 8 이번 1차 검토본의 완료 기준

1. 참여자·단말·서버·데이터 전달과 대화→기록→확정→공개 흐름을 문서만으로 이해할 수 있다.
2. 현재 구현과 미래 구상, 사용자 방향과 작성자의 제안을 구분한다.
3. 사용자가 제외하거나 보류한 범위를 지킨다.
4. 개인화의 주요 정보 흐름에 관한 통합 질문의 답변을 반영하거나 남은 미정을 명확히 표시한다.
5. 확인하지 않은 효과 수치·현장 실증·등록 가능성을 주장하지 않는다.
6. 잔여 질문 전부, 화면 첨부, 현장 비교 실험, 최종 청구범위 확정 없이도 1차 기술 검토 자료로 전달할 수 있게 정리한다.

## 9 전달 파일과 검증

전달 파일은 PDF와 Markdown 원본입니다. Word 형식도 검토했으나 현재 실행 환경에 Word 페이지 변환용 렌더러가 없어 검증되지 않은 DOCX는 전달하지 않습니다. PDF는 번들 Python의 ReportLab과 저장소 Pretendard 폰트로 생성하고 번들 Poppler로 페이지 이미지를 렌더링해 확인했습니다. 도면은 실제 서비스 화면이 아닌 시스템·처리 흐름의 설명도입니다.

최종 확인 범위는 7쪽, 도면 3개, 표·한글·쪽 번호·배치, 내부 질문 번호·저장소 경로 제거, 사용자 제외 범위, Markdown 이미지 링크 및 PDF 텍스트 포함 여부입니다. 제품 동작 테스트·배포·DB 쓰기는 수행하지 않았습니다. 외부 발송은 실행하지 않았습니다.
