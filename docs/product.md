### 0-1. 한 문장 정의

| | |
|---|---|
| 변경 전 | 요양보호사 업무를 전반적으로 돕는 도구 (회상 대화 + 요양일지 + 보호자 소통) |
| **변경 후** | **인지활동 프로그램을 AI 가 진행하고, 그 결과가 공단 형식의 프로그램 일지 초안으로 자동으로 남는 도구.** 요양보호사는 계획하고 감독하며 확인한다. 보호자는 어르신이 나눈 이야기를 받아 본다 |

### 0-2. 왜 바꿨나 — 우선순위 판단의 근거

1. **"업무 보조"로는 이길 수 없다.** 케어포·엔젤시스템·이지케어가 청구·급여기록·보호자 앱을 이미 갖췄고
   (엔젤시스템은 프로그램 일지·앨범의 보호자 앱 자동 전달까지 있다), AI 서류 초안 서비스도 나와 있다.
   → **기존 ERP 가 하는 기능은 만들지 않는다.**
2. **인지활동은 "의무인데 비어 있는" 영역이다.** 요양원은 주 3회 이상 프로그램을 운영해야 하고 기록이
   없으면 평가에서 깎이는데, 기존 ERP 의 인지활동 기능은 인쇄용 활동지·영상 콘텐츠 수준이다.
   어르신 한 분의 인생사에 맞춘 1:1 대화가 곧바로 공식 기록이 되는 것은 아무도 하지 않는다.
3. **회상 대화 기술 자체는 차별점이 아니다.** 대화형 AI 돌봄 서비스는 이미 있고 Gemini Live 같은 API 는
   누구나 쓴다. 차별점은 **시설의 업무 흐름과 기록 체계 안에 들어간다**는 것이다.
   → 대화 품질보다 **"대화 → 기록 → 확정 → 공유" 파이프라인의 완성도**가 더 중요하다.
4. **제도상 AI 혼자 진행하면 인정받기 어렵다.** 인지활동형 프로그램은 치매전문교육 이수자가 제공해야 한다.
   그래서 구조를 **"요양보호사 계획 → AI 진행 → 요양보호사 감독 → 요양보호사(또는 사회복지사) 확정"** 으로
   잡았다. 사람이 관여한 흔적(설계자·확인 여부·감독 기록)을 데이터로 남기는 것 자체가 기능이다.
5. **사용자 조건이 까다롭다.** 요양보호사는 대체로 고령이고 기기를 부담스러워한다 — 단계를 줄이고 입력을
   최소화한다. 보호자는 요양보호사에게 부담이 될까 먼저 묻지 못한다 — 먼저 알려 준다. 어르신은 기기를
   조작하지 않는다.
6. **돈 버는 구조와 맞아야 한다.** 시설에는 무료로 주고 정부 사업(용역·R&D)으로 수익을 낸다. 따라서
   "몇 번 제공했고, 기록이 얼마나 정확하고, 인력 시간을 얼마나 줄였나"를 **측정할 수 있어야** 한다.
   → 측정 가능한 이벤트 로그를 설계 초기부터 남긴다.

### 0-4. 핵심 흐름

```
[준비]  보호자가 연대기 소재 제공 → 요양보호사가 검수해 반영            (파일럿 범위 밖)
[계획]  월간 계획표 자동 초안(주 3회 충족 체크) → 사회복지사 확인        (파일럿 범위 밖)
[설계]  세션 설계(주제·피할 주제·목표 시간) → 요양보호사 확인
[진행]  기기 N대에서 1:1 세션 병렬 진행 — AI 가 대화
        요양보호사는 감독 화면으로 전체 상태 확인·개입
        위기 발화 → 즉시 중단 + 알림
[기록]  세션 종료 → 분석 레코드 → 프로그램 일지 초안 자동 생성(확인 대기)
[확정]  요양보호사/사회복지사가 확인·수정·확정                          (ERP 붙여넣기 복사는 범위 밖)
[공유]  공개 선택 → 보호자 웹 "오늘의 이야기"                          (카카오 알림톡은 범위 밖)
[관리]  현황판: 제공 횟수·참여율·확인 대기·누락 / "평소와 다름" 플래그   (파일럿 범위 밖 — 데이터는 지금부터)
```

**모든 단계가 "사람이 마지막에 확인한다"는 원칙을 지킨다.** AI 산출물이 사람 확인 없이 공식 기록이
되거나 보호자에게 나가는 경로는 없어야 하며, **테스트로 검증한다.**

## 2. 문제 정의

요양보호사 1명이 평균 5~10명의 어르신을 담당하는 구조에서, 어르신 개인의 기억과 삶에 맞는 1:1 인지치료는 현실적으로 제공이 불가능하다. 인지치료 전문 인력은 절대적으로 부족하고 비용도 높아, 대부분의 요양원에서는 치료 시간을 TV 시청이나 단순 체조로 채우는 실정이다. 기존 AI 스피커(KT 기가지니, SKT NUGU)는 안부 확인·말벗 수준에 그치며, 개인 연대기 기반 맞춤 대화와 세션 기록 기능은 없다.

> **핵심 문제:** 요양보호사 1명이 5~10명을 돌봐야 하는 현실에서, 어르신 한 분 한 분의 기억과 삶에 맞는 개인화된 음성 회상 대화를 제공할 방법이 없다.

## 4. 핵심 가치 제안

**① 요양보호사의 손이 닿지 못하는 시간을 AI가 채운다**
요양보호사가 연대기를 입력하면, 그 이후 AI가 어르신과 대화를 진행한다. AI가 요양보호사를 "대신"하는 것이 아니라, 요양보호사의 설계 의도를 실행하는 두 번째 손이다.

**② 어르신의 실제 삶에 기반한 개인화 대화**
출신지·직업·가족·주요 기억을 바탕으로 AI가 질문을 생성한다. 어르신이 낯선 AI가 아니라 "자신을 아는 누군가"와 대화하는 경험을 받는다.

**③ 세션 로그 자동 저장으로 기록 부담 제거**
세션 종료 후 대화 전문이 자동 저장된다. 요양보호사는 수기 없이 어르신의 반응과 대화 내역을 확인할 수 있다.

---

## 5. 사용자 시나리오

**시나리오 A — 요양보호사: 연대기 입력 및 세션 시작**
오전 9시, 김복순 요양보호사가 앱을 열고 이순자 어르신 프로필에 출신지(전주), 직업(식당 운영), 가족(딸 둘), 기억에 남는 일(남편과 처음 만난 장터)을 입력하고 저장한다. 세션 시작 버튼을 탭하면 AI가 자동으로 어르신에게 말을 건다. 요양보호사는 그 사이 다른 어르신을 케어한다.

**시나리오 B — 어르신: AI와 음성 회상 대화**
이순자 어르신이 스마트폰 앞에 앉는다. AI 음성이 흘러나온다. "어르신, 전주에서 오래 사셨다고 하셨는데, 거기서 제일 기억에 남는 게 뭐예요?" 어르신이 음성으로 답하면 AI가 다음 질문으로 자연스럽게 이어간다. 어르신이 짧게 답하거나 침묵하면 AI가 더 쉬운 질문으로 바꾼다.

**시나리오 C — 요양보호사: 세션 로그 확인**
세션 종료 후 요양보호사가 로그 화면을 연다. 이순자 어르신이 오늘 어떤 말을 했는지, 몇 턴 대화했는지 전문으로 확인한다. 다음 세션 전에 이 내용을 참고해 연대기를 보완한다.

## 7. 경쟁 서비스 대비 차별점

> ⚠️ 당시 비교다. 현재 경쟁 구도(ERP 공존·AI 서류 서비스·대화형 AI)는 §0-6.

| 항목 | KT·SKT AI 돌봄 | 기억온 |
|---|---|---|
| 인지활동 기능 | 없음 | 개인 연대기 기반 회상 대화 AI |
| 개인 맞춤화 | 없음 | 요양보호사 입력 연대기 기반 1:1 맞춤 |
| 요양보호사 도구 | 없음 | 연대기 입력 + 세션 설계 화면 |
| 세션 기록 | 없음 | 대화 전문 자동 저장 |
| 양방향 음성 | 없음 | TTS + STT 완전 양방향 |

기존 AI 스피커 서비스는 매 대화가 초기화된다. 기억온은 요양보호사가 입력한 연대기를 유지하여 세션마다 일관된 개인화 대화를 제공한다.

## 9. MVP 범위

> ⚠️ 2026-06 학기 MVP 범위다. 현재 파일럿 범위는 [`requirements.md`](requirements.md) §0 · 파일럿 계획 §2.

**이번 학기 목표:** 연대기 입력 → LLM 대화 생성 → TTS 출력 → STT 입력 → 세션 로그 저장까지의 핵심 파이프라인을 완성하고, 현장 파일럿 1회 이상 진행한다.

```
요양보호사 연대기 입력 (M-01)
        ↓
LLM 맞춤 회상 질문 생성 (M-02)
        ↓
TTS 음성 출력 → 어르신 청취 (M-03)
        ↓
STT 음성 입력 → 텍스트 변환 (M-04)
        ↓
세션 로그 자동 저장 → 요양보호사 확인 (S-01)
```

**파일럿 성공 기준:**
- 요양보호사가 연대기 입력 후 5분 이내 세션 시작 가능
- 어르신이 3턴 이상 대화 지속
- 세션 로그 자동 저장으로 수기 기록 불필요
- 요양보호사 만족도 5점 만점 기준 4점 이상

**이번 학기 제외 범위:**
보호자 앱 및 리포트 기능 / 인지자극 모듈 / 감정 분석 / 음악·미술치료 / 기관 어드민 / 수익화 기능
