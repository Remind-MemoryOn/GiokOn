## 원인과 확정 범위

1. **지연:** 앱이 전사 없는 발화의 마지막 유효 음량 뒤 6초 무음을 기다린다(`endpoint.ts`). 이후 Gemini Live의 전체 턴 완료 → 출력 검증 → 별도 Gemini TTS 합성 → 앱 입력/응답 저장 → 재생을 순서대로 기다린다. 실측으로 녹음 종료 후에도 12.7~13.4초가 소요됐다. 전사 수신은 첫 입력 종료 후 약 0.4초였다. 나머지를 모델 생성·TTS·네트워크 각각 몇 초라고 분리할 로그는 현재 없으므로 단정하지 않는다. DB의 사용자 `spoken_at`은 이 경로에서 응답 준비 후 채택 시각이므로 실제 발화 종료 시각으로 사용하면 안 된다.
2. **끼어들기 미지원:** `automatic.ts`는 재생 완료 후에만 청취를 시작한다. 앱·중계 모두 재생 완료 영수증 전의 새 입력을 차단하며 `interrupted` 재생 결과는 오류/회수로 취급한다. Gemini의 `NO_INTERRUPTION`만 바꿔도 앱이 별도로 재생 중인 TTS가 멈추는 것은 아니다.
3. **마지막 중단:** 청취가 약 20초 후 끝난 패턴은 입력 경계의 `no_input` → 빈 전사 콜백 → `AutomaticConversation.receive`의 ‘말씀을 확인하지 못했어요’ 중단 경로와 일치한다. 서버가 답변 의미를 종료 요청으로 분류한 것이 아니다. **음성을 놓친 이유**는 재생 중 발화 또는 고정 RMS 0.015 아래의 발화 가능성이 남는다. 이전 진단은 연결 전체 집계라 마지막 청취만의 음량을 복원할 수 없다. 전체 284청크 중 기준 이상 7청크·최대 RMS 0.027187·완전 무음 청크 0이었으며, 이것을 마지막 답변이 확실히 작았다는 증거로 쓰지 않는다.
