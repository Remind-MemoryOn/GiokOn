## T28.2 — 앱 계약·저장 (✅ 코드 2026-10-14)

- 사진 base64에서 패딩 길이를 두 번 빼던 오류 수정. 실제 PNG/JPEG의 전체 바이트와 끝부분 보존을 검사한다.
- 동기화 시작 후 사람이 확인한 안전 이벤트의 확인 시각을 오래된 응답으로 덮지 않는다. 서버 확인 저장은 후속 동기화한다.
- 순수 휴식·거부는 명시적인 마무리 동작으로 중계의 고정 인사만 받아 재생하고 종료를 기다린다. 마이크·재개를 다시 열지 않는다.
  위기·급성 고통이 섞인 요청은 즉시 정지한다. 일반 애도의 지지 권고는 긴급 중단으로 오인하지 않으며 턴 상한은 유지한다.
- 즉석 세션 생성에 시도별 UUID를 고정하고 응답 유실 시 동일 id·진행자·어르신·실행 상태만 조회해 복구한다.
  다른 기기의 실행 중 세션을 추측해 인수하지 않는다. `expo-crypto`는 기존 간접 설치 버전을 직접 의존성으로 선언했다.
- 주제 분석의 빈 목록용 전사 대신 저장된 참여도와 실제 발화 수를 가중 집계한다. 관찰 없음과 관찰된 0%를 구분한다.

기존 코드에서 사진·안전 확인·마무리 회귀 12개, 세션 생성 복구 회귀 10개가 실패함을 확인한 뒤 수정했다.

## T28.4 — 확정 기록·첨부 보존 (✅ 코드·로컬 검증 2026-10-14)

확정 일지의 직접 삭제 RLS는 상위 세션·어르신 삭제의 FK cascade를 막지 못했다. API 역할의 cascade에도 동작하는
DELETE 트리거를 추가했다. 승인된 운영자 역할의 파기는 유지한다. 확정 또는 현재 공개 중인 사진은 Storage 객체의
교체·이름 변경·삭제도 막으며, 다른 기관의 임의 메타데이터 경로가 내 기관 객체를 잠그지 않도록 기관을 함께 검사한다.
클라이언트는 파일 파기 전에 확정 일지를 확인하고, 조회 실패도 삭제를 멈춘다. Storage가 오류 없이 0개 삭제를 반환하면
무한 반복·거짓 성공 대신 중단하고, 일부 삭제만 성공하면 실제 삭제 수로 다음 페이지를 처리한다.

새 로컬 PostgreSQL 16에 전체 마이그레이션 84개와 권한 심을 적용한 뒤 SQL 회귀 17개 통과.
상위 cascade·Storage UPDATE·DELETE·새 경로 WITH CHECK·기관 필터를 각각 제거한 변이 5개 모두 검출.
CI에도 기존 로컬 전용 Storage·자동 철회·동의 철회·운영 스키마 권한 회귀를 연결했다.
**운영 미적용**: main 병합 시 Supabase 연동이 자동 적용하므로 승인 후 병합·운영 버전 대조가 필요하다.
파일 파기와 DB 삭제는 원자적이지 않다. 사전 검사 직후 다른 사람이 확정하면 최종 기록은 DB가 지키지만,
이미 삭제한 미확정 파일·프로필 사진까지 복원하지는 않는다.

## T28.3 — 웹 공개·입력·분석 (✅ 코드 2026-10-14)

- 사진 목록을 확인하기 전에 일지만 철회하고 성공을 표시하던 경로를 막았다. 기존 공개 사진의 체크 상태도 목록이 도착한 뒤 초기화한다.
- 공개 저장 도중 중복 조작을 막고 성공 후 설정 주소를 닫는다. 공개 항목은 `(유형, id)`로 구분한다.
- 운영 시각의 시 또는 분을 비우면 전체 시각을 비워 `null`로 저장한다.
- 기관 설정 조회 중/실패 상태에서 장기요양등급 필요 여부를 추측해 등록·수정하지 않는다.
- 주요 기억이 시안의 2행을 넘으면 특이사항·저장 버튼도 같은 간격으로 내려 겹치지 않는다.
- 연대기 날짜를 한국 날짜로 읽고 한국 자정으로 저장해 반복 수정 시 하루씩 앞당겨지는 오류를 막았다.
- 전체·개인 분석의 횟수·주제·키워드·요약은 선택 기간과 같은 범위를 쓴다. 기존 관찰 집계의 30일 단위는 유지했다.
- 미측정 월은 그래프 선을 끊고 관찰된 0은 실제 점으로 남긴다. 주제 비중만으로 장기 변화를 단정하지 않는다.

공개·연대기·기관 등급·일지·그래프·분석 기간 브라우저 회귀와 기존 인증·기관·설계·삭제·반응형·감독·디자인 수정 회귀 통과.
감사 데이터의 잘못된 `topicOutcomes.turns`를 계약의 `elderTurns`로 수정하고, 기간 목록은 상대 날짜로 심어 시간이 지나도
시안의 행 수를 검사한다. Figma 좌표·잉크의 기준값과 허용 오차는 바꾸지 않았다.

- 보안 advisor 경고를 0건으로 표현하지 않는다. RPC definer 권한 경고와 유출 비밀번호 보호 비활성이 남는다.
  공개 로그인 찾기(마스킹)·문의 목록(비공개 제목 차단)은 의도된 RPC이며 운영 정의를 확인했다.
  `rls_auto_enable`은 플랫폼 이벤트 트리거 반환 함수로 확인했고 프로젝트 마이그레이션에서 임의 변경하지 않았다.
  워커/제품 이벤트/음성 점유의 무정책 RLS는 직접 API 접근을 닫는 설계다.
  [Supabase definer 검사 설명](https://supabase.com/docs/guides/database/database-linter?lint=0028_anon_security_definer_function_executable),
  [비밀번호 보호 설명](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection).
