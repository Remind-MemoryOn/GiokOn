# 재생 중 발화·2초 발화 경계 구현 계획

> 실행: superpowers:executing-plans로 각 단계의 실패 회귀 → 구현 → 검증 → 기록을 수행한다.

**목표:** 에코 제거된 마이크를 TTS 중에도 열고, 어르신 발화 때 TTS를 중단해 입력을 이어 받는다. 발화 종료는 무음 2초로 판정한다.
**구조:** 검증된 TTS 경로는 유지한다. 앱 전용 네이티브 모듈이 동시 녹음/재생과 OS 에코 제거를 소유한다. 중계 프로토콜 v4가 `interrupted` 재생 영수증을 지원하고, 앱은 기존 재생 관찰 저장 계약에 중단을 남긴다. v1~3 앱의 동작은 유지한다.
**스택:** Expo SDK54·Kotlin AudioRecord/AudioTrack/AEC·Swift AVAudioEngine VoiceProcessing·TypeScript·Node ws.
**요구 근거:** `2026-10-16-voice-turn-experience.md` 및 2026-10-16 사용자 구현 지시.

## 제약·검증 초점

- 모델 원음을 재생하거나 출력 검증/위기 즉시 중단/10분 상한을 약화하지 않는다.
- 에코 제거 초기화 실패는 무처리 오디오로 대체하지 않고 명시적 실패로 닫는다.
- 재생 중단을 완료로 기록하지 않는다. 중단 직후 사용자 발화 앞부분은 제한된 메모리 버퍼로 보존한다.
- 재생 끝과 발화가 동시에 발생해도 입력/재생 영수증은 한 번만 보낸다.
- 회수·백그라운드·권한 상실 뒤 늦은 네이티브 콜백으로 마이크를 다시 열지 않는다.
- 기기별 AEC 성능은 네이티브 빌드 성공만으로 검증됐다고 하지 않는다.

## 3초 이내 첫 응답 권고

### 2026-10-17 16:02 재검증 — 공급자 턴 종료 대기가 주 병목

- ✅ 사용자 실기기 확인: 작은 목소리 입력, 첫 내용 보존, 약간의 주변 소음 처리 모두 양호. 이는 해당 Lenovo 기기·환경 결과이며 모든 기기 품질 보장은 아니다.
- 운영 `00010-hbx`의 대답 3턴: 입력 종료→생성 완료 2.169/3.108/3.668초, 합성 5.396/7.642/8.380초, 입력 종료→앱 전송 11.022/16.682/18.818초. 합성은 생성 완료부터 겹쳐 수행되므로 이 시간을 단순 합산하지 않는다.
- 마지막 턴은 16:03:20.658 입력 종료, 16:03:24.326 생성 완료, 약 16:03:32.706 합성 완료, 16:03:39.476 전송이다. 합성이 끝난 뒤에도 약 6.8초를 기다렸다. 전체 문장은 3.7초에 완성됐으므로 18.8초를 순수 추론으로 설명하면 틀린다.
- DB 내용 원문 없이 길이만 대조: 사용자 30/27/107자, AI 71/111/129자. 지연은 입력 길이만으로 단정할 수 없고, 긴 AI 답변과 공급자 원음 재생 대기·합성이 함께 늘었다. 앱 AI 기록 시각은 전송 후 약 0.3~0.4초이나 실제 스피커 시작 시각을 보장하지 않는다.
- 사용자가 체감한 약 30초 전부는 현재 계측으로 입증하지 못한다. 마지막 발성→activityEnd 시간과 실제 재생 시작 계측이 없어, 확인된 서버 18.8초 외 나머지를 임의로 추론하지 않는다. 태블릿은 `.42` 연결 실패, mDNS로 기존 `.43` 연결 확인; 해당 시간 앱 오류 로그 없음.
- ⏳ 우선 수정 방향: 생성 완료·검증·합성 완료 이후 공급자의 원음 재생 대기와 앱 전달을 분리한다. 단순히 turnComplete 조건을 지우면 늦은 이전 턴 완료가 새 입력과 섞이므로 공급자 턴 종료/앱 재생/다음 입력을 별도 상태로 다루고 중단·위기·회수 회귀를 선행해야 한다.

2초 무음 뒤 전체 응답을 3초 이내에 시작하려면 모델 생성·검증·합성·저장·전송에 남는 예산은 약 1초다. 이전 실측은 녹음 종료 뒤만 12.7~13.4초였으므로, 이번 변경으로 3초를 달성했다고 말하지 않는다.

1. **우선 권고: 전체 응답 텍스트 검증 뒤 TTS 스트리밍.** 현재는 한 턴 음성 전체 합성을 기다린다. Gemini 3.8 TTS는 streaming PCM(24 kHz mono)을 지원한다([공식 문서](https://ai.google.dev/gemini-api/docs/speech-generation#streaming-speech-generation), 2026-10-16 확인). 첫 청크부터 재생하도록 중계/앱의 청크·취소·완료 계약을 확장하면 나머지 음성 합성 대기를 줄일 수 있다. 전체 텍스트 안전 검증·PCM 형식 검증·중단 관찰은 유지한다. 이번 요청의 추천 항목으로 남기며 임의로 합성 프로토콜까지 바꾸지는 않는다.
2. 추가한 중계 turn_latency의 modelMs/synthesisMs/totalMs로 병목을 분리한다. 값은 activityEnd 이후이며 2초 무음과 앱 DB 저장/재생 준비는 포함하지 않는다. 사용자 발화 시각을 DB spoken_at으로 대신하지 않는다.
3. 모델 생성 자체가 지배적이면 스트리밍 STT → 짧은 텍스트 생성 → 검증 → 스트리밍 TTS 분리를 비교 시험한다. 현재 음성 모델의 출력 형식만 TEXT로 바꾸는 것은 호환 보장이 아니다. 2초 경계를 더 줄이면 느린 어르신 발화를 자를 수 있으므로 기기 음성 평가 없이 일괄 축소하지 않는다.

**기존 정책과 차이:** 재생 완료 뒤 녹음 시작하던 순차 흐름을 사용자 승인에 따라 동시 입출력으로 바꾼다. Gemini 원음 재생/안전 판정 우회/위기 즉시 종료 완화는 없다. 진짜 무음 20초 뒤 미인식 중단은 이번 2초 발화 경계 변경과 별개로 유지하며, 재청취 정책은 후속이다.
