# DB 제외 개발 목록 — 2026-09-13

## 범위와 판단 기준

9월 13일 사용자 요청으로 승인된 개발 방향을 실행 단위로 정리했다. 프로젝트 사실의 SoT는 [AGENTS.md](../../AGENTS.md), 사업 범위는 [D1~D11](business-plan-development-delta.md), 음성 설계는 [음성 AI 계획](voice-ai-personalization.md)이다. 문서 반영 완료와 아래 기능 개발 완료는 다르다.

- 포함: 모바일·웹·공유 패키지·음성 중계 서버·Edge Function·외부 API 연동·계측·빌드 및 검증 자동화.
- 제외: 테이블/컬럼·SQL·RLS·트리거·RPC 구현·마이그레이션·DB 운영 적용. 필요한 데이터 계약은 의존성으로만 표시한다. DB를 제외한다는 뜻은 서버 개발을 제외하거나 클라이언트만으로 보안을 보장한다는 뜻이 아니다.
- 현재 상태는 저장소 코드와 기존 검증 기록의 대조다. 이번에는 실기기·운영 API·DB를 재검증하지 않았다. 전체 감사의 신규 전수 재감사도 아니므로 기존 R 항목의 판정을 대체하지 않는다.
- `신규`: 목표 기능 미구현. `보강`: 기반 구현에 새 동작/실패 처리가 필요. `검증`: 기존 구현을 새 인수 조건으로 확인하며 실패 시 수정. 아래 항목은 모두 미완료다.
- 단계는 개발 순서다. 기존 감사의 P0/P1 위험도를 낮추거나 출시 차단 조건을 면제하지 않는다.

## 승인된 개발 방향과 순서

1. 서버 통제 경계·턴 상태·기록 출처·계측 계약을 먼저 정한다.
2. R013 이후 공통 권한·공개·무결성 과제를 유지한다. 이 목록에는 그중 앱/웹/서버 연동만 포함한다. DB 작업 완료가 필요한 배포는 해당 검증 전 진행하지 않는다.
3. 자동 진행·검증 출력·최소 지원 정책·계측을 한 세션의 시작부터 회수까지 연결한다. 기존 확인 패널을 위한 수정은 새 상태 흐름에 필요한지 먼저 판단한다.
4. 현장 테스트 전 일지 승인·오류 복구·담당자 대응·측정을 완성한다. 지원 경로 없는 단독 운영을 검증됐다고 표시하지 않는다.
5. 첫 유료 도입 전 초안 품질·실제 사용량·요금 정책을 검증한다. 독립 학습과 외부 업무 시스템 연동은 후속이다.

추천 음성 중계 구조를 개발 기준으로 채택했다. 호스팅 사업자·리전·배포 도구·용량은 미정이다. Supabase 인증/데이터 접근은 유지하고, 장시간 연결 실행 환경을 별도로 선정한다. 기존 Supabase 함수 배포는 CLI 우선 원칙을 유지한다.

## 이미 있는 기반 — 다시 신규 개발로 세지 않는다

- Gemini Live 입력·전사·수동 확인과 PCM 재생: `apps/mobile/src/lib/live/`, `app/session/talk.tsx`. 자동 진행·Clova 출력은 별도 신규 작업이다.
- 규칙 일지: `packages/core/src/journal.ts`; 웹 연결: `JournalWritePage.tsx`. 실제 생성형 LLM은 아직 없다.
- Realtime 추가 6종은 `packages/data/src/hooks/realtime.ts`의 타입·기본 구독·무효화에 모두 있다. 남은 것은 N20 검증이지 같은 테이블 등록의 반복이 아니다.
- 기존 인증 경계·권한/동의 가드·토큰 발급 제한과 R005~R012 근거는 [보안 런북](../runbooks/p1-remediation-progress.md)에 유지한다. R010은 부분 해결이다.
- CI에는 품질 검사·웹 인증 격리·RLS 회귀·SCA가 있다. 모바일 수동 게이트와 새 기능 E2E의 공백을 보강한다.

## 코드 개발 목록 밖의 출시 의존성

음성 처리 계약·데이터 흐름 검토, Clova 계정, 중계 실행 환경, 도메인/DNS·SMTP·OAuth 콘솔, 법인/보호책임자·고지 문구, 스토어 계정, 시설 테스트 동의·책임자·대응 경로, 가격·결제 조건은 별도로 완료해야 한다. 이 목록을 작성했다고 충족되거나 실기기 검증이 끝난 것은 아니다. `.env` 등 민감 파일 접근 금지는 유지한다.
