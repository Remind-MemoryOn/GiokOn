# 음성 전환 단계별 구현 계획

기준: [N01~N35](non-db-development-backlog.md), [승인 음성 설계](voice-ai-personalization.md) §3.4. 2026-09-13 사용자 지시로 태스크별 개발을 시작한다. DB 변경·민감 파일 접근 없이 기존 main에서 순차 진행한다. 각 태스크는 실패 테스트→최소 구현→회귀 검증→진행 기록 순서로 수행한다.

## 첫 묶음: 계약과 실행 규칙

### T01 / N02 — 자동 대화 전이와 오래된 응답 거부

- 파일: `packages/core/src/voice-flow.ts`, `voice-flow.test.ts`, `index.ts`.
- 입력: `VoiceFlowState`, `VoiceFlowEvent`. 출력: `transitionVoiceFlow(state, event)`의 새 불변 상태. 생성은 `createVoiceFlow(sessionId, connectionId)`.
- 연결 식별자는 재연결/재생성마다 새 값으로 발급한다. session/connection/generation/turn과 요청 시작 phase가 같은 이벤트만 처리한다. 식별자는 인가 토큰이 아니다.
- 정상 경로: ready→listening→awaiting→validating→synthesizing→speaking→listening. 중단/철회는 ended, 휴식/오류/불명확은 paused. 재개 시 새 generation을 사용한다.
- [x] 실패 테스트: 검증 전 재생, 단계 역전, 이전 턴/연결/세션, 휴식·회수 이후 늦은 완료, 중복 완료, 종료 후 재개를 거부한다.
- [x] 순수 reducer와 타입을 구현하고 위 테스트를 통과한다. 외부 I/O·기존 화면 배선은 포함하지 않는다.
- [x] core 전체 테스트·타입 검사, 모노레포 타입 검사와 문서/차이 검사를 실행한다. 상태 규칙 통과를 실제 오디오 취소 완료라고 기록하지 않는다.

2026-09-13 T01 구현: 신규 21개·core 전체 228개 통과, 모노레포 typecheck/lint 통과. 테스트는 envDir=false로 환경 파일을 로드하지 않았다. 요청 시작 단계가 지난 뒤 도착한 오류도 거부한다. N02의 상태 규칙 부분만 완료이며, 실제 I/O 취소·인가·연결 ID 발급·앱 배선·실기기 검증은 미완료다.

예시 인수 조건:
```ts
const ready = createVoiceFlow('session', 'unique-connection')
const listening = transitionVoiceFlow(ready, { type: 'start' })
const ended = transitionVoiceFlow(listening, { type: 'end', reason: 'retrieved' })
expect(transitionVoiceFlow(ended, { type: 'resume' })).toBe(ended)
```

### T02 / N01 — 중계 메시지·인가 경계

- 서버/앱 메시지의 런타임 검증과 프로토콜 버전, 본문/오디오 제한을 정의한다. T01 식별자를 공유하고 외부 입력을 타입 단언만으로 통과시키지 않는다.
- 세션·기관·배정·동의·한도 검사 실패 시 연결을 거절한다. 기존 직접 연결 우회·구버전 전환은 배포 선행 조건이다.
- 호스팅 미정 상태에서 특정 사업자 SDK를 추가하거나 운영 연결을 변경하지 않는다. 실행 환경 선택 전 로컬 계약 시험까지만 완료로 판정한다.

### T03 / N03 — 전사·생성·채택·실제 전달 계약

- 원전사, 대화 채택 해석, 사람 교정 출처 및 생성/승인/재생 결과를 분리한다. 자동 채택을 사람 확인이나 당일 관찰로 표시하지 않는 매핑을 검증한다.
- T01의 playback 완료만 실제 음성 전체 전달로 인정하며 중간 중단은 별도 결과다. 저장 구조는 DB 파트와 계약 후 연동한다.

### T04 / N04 — 시간·원가 계측 계약

- 단조 시간 기준 발화 종료→첫 검증 음성 재생과 담당자 실제 투입 시간을 측정한다. 결측 null, 유효하지 않은 시간 거절, 동일 이벤트 재전달 중복 집계 방지.
- 공급자 사용량과 가격 추정·실제 청구를 구분한다. 일반 로그에 원전사·음성·개인정보를 넣지 않는다.
