## 첫 묶음: 계약과 실행 규칙

### T01 / N02 — 자동 대화 전이와 오래된 응답 거부

- 파일: `packages/core/src/voice-flow.ts`, `voice-flow.test.ts`, `index.ts`.
- 입력: `VoiceFlowState`, `VoiceFlowEvent`. 출력: `transitionVoiceFlow(state, event)`의 새 불변 상태. 생성은 `createVoiceFlow(sessionId, connectionId)`.
- 연결 식별자는 재연결/재생성마다 새 값으로 발급한다. session/connection/generation/turn과 요청 시작 phase가 같은 이벤트만 처리한다. 식별자는 인가 토큰이 아니다.
- 정상 경로: ready→listening→awaiting→validating→synthesizing→speaking→listening. 중단/철회는 ended, 휴식/오류/불명확은 paused. 재개 시 새 generation을 사용한다.
- [x] 실패 테스트: 검증 전 재생, 단계 역전, 이전 턴/연결/세션, 휴식·회수 이후 늦은 완료, 중복 완료, 종료 후 재개를 거부한다.
- [x] 순수 reducer와 타입을 구현하고 위 테스트를 통과한다. 외부 I/O·기존 화면 배선은 포함하지 않는다.
- [x] core 전체 테스트·타입 검사, 모노레포 타입 검사와 문서/차이 검사를 실행한다. 상태 규칙 통과를 실제 오디오 취소 완료라고 기록하지 않는다.

2026-09-13 T01 구현: 신규 21개·core 전체 228개 통과, 모노레포 typecheck/lint 통과. 테스트는 envDir=false로 환경 파일을 로드하지 않았다. 요청 시작 단계가 지난 뒤 도착한 오류도 거부한다. N02의 상태 규칙 부분만 완료이며, 실제 I/O 취소·인가·연결 ID 발급·앱 배선·실기기 검증은 미완료다.

예시 인수 조건:
```ts
const ready = createVoiceFlow('session', 'unique-connection')
const listening = transitionVoiceFlow(ready, { type: 'start' })
const ended = transitionVoiceFlow(listening, { type: 'end', reason: 'retrieved' })
expect(transitionVoiceFlow(ended, { type: 'resume' })).toBe(ended)
```

### T02 / N01 — 중계 메시지·인가 경계

- 서버/앱 메시지의 런타임 검증과 프로토콜 버전, 본문/오디오 제한을 정의한다. T01 식별자를 공유하고 외부 입력을 타입 단언만으로 통과시키지 않는다.
- 세션·기관·배정·동의·한도 검사 실패 시 연결을 거절한다. 기존 직접 연결 우회·구버전 전환은 배포 선행 조건이다.
- 호스팅 미정 상태에서 특정 사업자 SDK를 추가하거나 운영 연결을 변경하지 않는다. 실행 환경 선택 전 로컬 계약 시험까지만 완료로 판정한다.

2026-09-13 1차 구현: `apps/voice-relay`에 WSS WebSocket 경계, 세션별 Supabase JWT·`can_process_session` 검사, 연결/전송량/버퍼/시간/턴 제한, 권한 재검사, 앱 단절 시 공급자 종료를 구현했다. 모바일은 `EXPO_PUBLIC_VOICE_RELAY_URL`이 있을 때만 이 경로를 사용하고, 주소가 없으면 기존 직접 Live 경로를 유지한다. 로컬 실제 WebSocket과 가상 공급자 회귀 시험은 통과했지만 운영 호스팅·WSS 인증서·구버전 직접 경로 차단은 미완료다.

### T03 / N03 — 전사·생성·채택·실제 전달 계약

- 원전사, 대화 채택 해석, 사람 교정 출처 및 생성/승인/재생 결과를 분리한다. 자동 채택을 사람 확인이나 당일 관찰로 표시하지 않는 매핑을 검증한다.
- T01의 playback 완료만 실제 음성 전체 전달로 인정하며 중간 중단은 별도 결과다. 저장 구조는 DB 파트와 계약 후 연동한다.

2026-09-13 1차 구현: 중계 서버는 Gemini 원본 오디오를 폐기하고 출력 전사만 길이·안전 규칙으로 검사한 뒤 Clova Voice에서 생성한 24kHz mono PCM만 앱에 전달한다. 합성 중 권한 철회·취소·오류는 음성을 보내지 않고 연결을 종료한다. 의미·개인 사실에 대한 독립 검수와 영속화 출처 필드는 아직 남아 있다.

### T04 / N04 — 시간·원가 계측 계약

- 단조 시간 기준 발화 종료→첫 검증 음성 재생과 담당자 실제 투입 시간을 측정한다. 결측 null, 유효하지 않은 시간 거절, 동일 이벤트 재전달 중복 집계 방지.
- 공급자 사용량과 가격 추정·실제 청구를 구분한다. 일반 로그에 원전사·음성·개인정보를 넣지 않는다.

## 후속 구현 묶음

### 2026-09-20 — T03a 전사 채택 출처의 런타임·기존 저장 경계

- `ConversationTurn.provenance`: `unknown` / `automatic` / `caregiver_confirmed`를 구분한다. 누락도 unknown이며 정확성·동의·실제 청취의 증거가 아니다.
- 앱 `confirmUtterance`의 명시적 확인 동작만 caregiver_confirmed를 부여한다. `presentedText`는 확인 전에 표시된 입력(직접 입력 전 빈 패널이면 null)이며 음성과 일치하는 원전사라고 주장하지 않는다. 최종 문장은 text, 수정 전 원문은 기존 originalText로 유지한다. 빈 확인은 턴을 생성하지 않는다.
- 기존 DB 조회는 original_content 존재 여부와 무관하게 unknown으로 읽는다. 수동 확인 기록은 기존 스키마로 계속 저장하지만 새 런타임 메타데이터는 영속화되지 않는다. 따라서 재조회 후 확인 여부를 복원하거나 표시할 수 없다.
- 자동 채택 턴은 기존 insert 매퍼에서 `TRANSCRIPT_PROVENANCE_STORAGE_REQUIRED`로 거절한다. 일괄 insert 이전 매핑에서 거절되며 자동 진행은 아직 활성화하지 않는다.
- 회귀 6건은 변경 전 실패/변경 후 통과했다. 전체 자동 테스트 477건(core 234/data 116/mobile 108/relay 19), 전체 typecheck·lint, copy/BOM/font/figma 검사 통과. 네이티브 코드·의존성 변경은 없으며 이번 테스크에서는 번들 생성·실기기 검증을 수행하지 않았다.

**후속 T03b(DB 의존 계약, 이번에 미수행)**: 세션 로그에 원전사와 공급자 출처, 채택 방식, 사람 확인자/확인 시각 및 교정 이력을 보존하는 버전 계약이 필요하다. 확인자·시각은 클라이언트 주장만으로 확정하지 않고 서버가 인증·권한을 검사한다. 과거 행은 unknown을 유지하고 자동 채택을 확인 완료로 소급 변환하지 않는다. 스키마/RPC·매퍼 왕복 시험을 함께 연결한 후에만 자동 채택 저장 차단을 해제한다. 원전사/채택/재생 결과의 영속화와 N08 자동 루프 전체는 여전히 미완료다.

2026-09-19 재개 검증: 아래 T03/N09 변경은 자동 테스트 471건(core 234/data 114/mobile 104/relay 19), 전체 typecheck·lint, copy/BOM/font/figma, Android·iOS JS 번들이 통과했다. 중계 응답은 60초까지 기다리며(직접 연결 20초), 중계 모드에서는 로딩 화면으로 이동하지 않아 연결·오디오 캐시·완료 상태를 유지한다. 첫 응답 실패와 요청 예외도 회수 안내로 처리한다. 운영 배포·DB 변경·실기기 검증은 포함하지 않는다. 사용자 지시에 따라 각 테스크는 검증·기록 후 개별 커밋한다.

### 2026-09-14 재개 — T03/N09 재생 완료와 다음 입력 경계

시연 성공을 사용자에게 확인받은 후 자동 대화 개발을 재개했다. 자동 청취의 전제인 재생 완료 계약부터 실제 I/O에 연결했다.

- `player.ts`: 완료/중단/빈 오디오를 구분한다. 재생 로드 중 회수와 재생 중 회수를 정상 완료로 취급하지 않는다.
- `client.ts`·`engine.ts`: 중계 v2 협의, 응답 턴 번호 검사, 재생 완료 통지. 통지 전 마이크 입력·새 응답 요청 차단. 중단 시 연결 종료.
- `relay.ts`: 완료 통지 전 다음 입력 거부, 동일 턴·현재 권한 검사, 95초 미확인 종료. v1 호환 경로는 유지하되 자동 대화 기준으로 표시하지 않는다.
- `talk.tsx`: `finally`에서 재생 완료 표시하던 경로를 제거하고 실제 완료 결과일 때만 표시한다.
- 회귀: 기존 재생 결과 구분 4건·중계 다음 입력 2건·클라이언트 버전/완료 확인 2건·엔진 전달 결과 3건이 수정 전 실패하고 수정 후 통과했다. 중단/잘못된 턴 거절도 추가 확인했다.

이 작업은 자동 대화의 재생/전송 전제다. 매 턴 확인 UI는 아직 유지된다. 다음 작업은 T03 자동 채택과 사람 확인 출처 분리→N08 시작/회수 루프→일시정지 후 맥락 복구다. 서버 우선 갱신이 필요하며 이번에는 운영 배포·실기기 검증·DB 변경을 수행하지 않았다.
