# 앱·웹 시연 영상 촬영 준비 점검

> ⚠️ **당시 기록(2026-09-13~14 시연 촬영 준비)이다.** 2026-09-23 기획 변경으로 요양일지 흐름·직접 Gemini Live 경로는 폐기됐다.
> 현재 계획은 [`pilot-development-plan.md`](pilot-development-plan.md). 여기 적힌 "대화 요약만 공개" 결함(`session_summary` 미렌더)은
> 파일럿 계획 W4 에 옮겨 두었다.

최초 점검일: 2026-09-13. 갱신일: 2026-09-14. 범위: 앱 대화 → LLM 분석 → 웹 대화 기록 → LLM 일지 초안·최종 저장·공개 → 보호자 코드 연결·열람.
최초 코드 점검 이후 LLM 생성 코드와 서버 함수 배포를 추가했다. 현재 검증 근거는 [실 API 시연 구현 진행](demo-llm-implementation.md)에 기록한다. 실제 계정·설치 앱·Gemini/CLOVA 실호출과 종단 리허설은 아직 미검증이다. `.env` 및 민감 파일에 접근하지 않았다.

## 결론

웹 기록 조회·일지 작성·공개·보호자 연결과 앱 분석은 구현돼 있다. 촬영을 위해 전체 개발 계획을 완료할 필요는 없다. 우선 실제 기기 음성 경로를 정하고, 동일 세션이 웹까지 이어지는 리허설을 통과시켜야 한다.

현재 앱은 매 턴 전사 확인·확정이 필요하다. 시작 후 자동으로 대화를 이어가는 목표 UI는 미구현이다. 이번 영상에서 현행 확인 흐름을 보여주면 자동 진행 개발은 촬영 후로 미룰 수 있다.

## 촬영 단계별 현황

| 장면 | 코드상 현황 | 촬영 전 남은 일 |
|---|---|---|
| 앱에서 대화 진행 | 마이크 PCM 입력·Live 응답·전사 확인 구현. 중계 주소 설정 시 검증 전사→Clova 출력 사용 | 설치 앱의 중계 설정 여부, 네이티브 마이크 모듈, 권한, 실제 음성 입출력 확인. Clova 경로면 WSS 서버 실행·인증값 등록·실호출 검증 필요 |
| 대화 종료·분석 | 종료 시 대화·기존 관찰 지표 저장. 분석 진입 시 LLM 요약·주제·일지 초안 생성 및 오류/재시도 구현 | 시연 계정 허용 등록 후 실제 생성·저장·재진입 유지 확인 |
| 웹에서 앱 대화 확인 | 동일 Supabase의 sessions/session_logs 조회, 말풍선 전문 표시 | 동일 어르신·접근 권한·세션을 사용해 마지막 확인 발화까지 대조 |
| 일지 작성 | 종료 세션 선택→LLM 초안 미리보기→명시적 본문 적용 구현. 직접 입력·규칙 기반 정리도 유지 | 실제 API 생성→담당자 수정·최종 저장→재조회 확인. 합성 API 브라우저 검증은 통과했지만 실제 저장 완료 근거는 아님 |
| 일지 공개 | 공개 관리에서 일지·사진을 선택해 guardian_shares 생성 | 승인된 보호자 연결과 이름이 있어야 공개 버튼 활성화. 일지 저장과 공개는 별도 단계 |
| 보호자 코드 연결 | 코드 요청→pending→담당 승인→approved 구현 | 새 보호자 계정 준비, 실제 코드 확보, 담당자의 승인 장면 또는 사전 승인 필요 |
| 보호자 공개 열람 | 공개된 일지 상세·사진·읽음 기록 구현 | 승인 후 같은 일지가 보이고 본문이 일치하는지 확인. 사진은 별도 공개 선택 필요 |

## 촬영 전 필수 작업

### D01 — 음성 경로 확정 및 실기기 연결 (최우선)

- `EXPO_PUBLIC_VOICE_RELAY_URL`이 있으면 신규 중계 경로, 없으면 기존 직접 Gemini Live 경로다. 실제 설치 빌드의 설정은 이번 점검에서 확인하지 않았다.
- CLOVA까지 시연하려면 중계 서버 실행 환경·유효한 WSS 주소, 서버 인증 설정, 앱의 공개 중계 주소 설정이 필요하다. 사용자 확인으로 CLOVA 신청·인증 준비는 완료됐지만 서버 등록·실호출 성공을 뜻하지 않는다.
- 기존 직접 Gemini 음성으로 촬영한다면 중계 배포를 촬영 뒤로 미룰 수 있다. 이 경우 영상에서 Clova 출력 완료로 소개하지 않는다.
- Expo Go 대신 마이크 모듈이 포함된 개발 빌드가 필요하다. 현재 EAS `preview`의 iOS 설정은 simulator 전용이므로 iPhone 설치용으로 그대로 사용하지 않는다.
- 첫 인사→마이크 입력→전사 확인→응답 재생→다음 턴→종료를 실제 기기에서 반복 확인한다. 실기기에서 드러나는 연결·전사·재생 오류만 우선 수정한다.
- 중계는 Gemini 생성과 Clova 합성을 순차 수행하지만 앱 응답 제한은 기본 20초다. 실제 응답 시간이 초과하면 촬영 중 중단되므로 지연을 재고, 필요할 때 중계 전용 제한/대기 처리를 조정한다. 현재 실패가 확인된 것은 아니다.

근거: `apps/mobile/src/lib/live/{client,engine,mic}.ts`, `apps/mobile/eas.json`, `apps/voice-relay/{README.md,src/relay.ts,src/output.ts}`.

### D02 — 계정·권한·연결 순서 준비 (필수, 주로 운영 준비)

- 웹·앱에서 같은 담당자 계정 또는 같은 어르신에 정식 배정된 계정을 사용한다. 기관 소속·어르신 배정·현행 필수 동의가 있어야 시작할 수 있다.
- 별도의 보호자 계정을 준비한다. 같은 로그인 계정에서 메뉴만 바꾸는 방식이 아니다. 브라우저 프로필을 나눠 두 계정을 유지하면 촬영 전환이 간단하다.
- 테스트용 가상 인물 프로필과 연대기를 정상 UI로 입력하고, 촬영 참여자가 직접 발화한다. 결과 지표·대화 기록을 코드에 하드코딩하지 않는다.
- 현재 사용자의 제안 순서인 **공개→첫 코드 연결**은 보호자 연결이 없는 상태에서 막힌다. `ShareSettingsDialog`가 승인된 보호자의 이름 없이는 공개를 허용하지 않는다.
- 권장 실제 작업 순서: **보호자 코드 입력→담당자 승인→앱 대화→웹 일지 최종 저장→공개→보호자 열람**. 연결 장면을 먼저 촬영해 두고 영상에서 뒤에 배치할 수 있다. 승인 절차를 생략한 기능처럼 설명하지 않는다.
- 승인 UI는 `/caregiver/org`, 코드 연결은 `/guardian`이다. 공개는 `/caregiver/shares/:elderId`에서 수행한다.

근거: `apps/web/src/components/share-settings.tsx`의 `canPublish`, `pages/caregiver/ShareItemsPage.tsx`의 `guardianName`, `pages/caregiver/OrgPage.tsx`, `pages/guardian/ConnectPage.tsx`.

### D03 — 앱→웹→보호자 종단 리허설 (필수)

다음 항목을 모두 실제 화면으로 통과하면 촬영 준비 완료로 판정한다. 기존 단위 테스트·JS 번들 성공은 이 검증을 대신하지 않는다.

- [ ] 앱에서 3~5회 실제 발화·확정을 진행하고 응답 음성이 들린다.
- [ ] 종료 후 저장 완료 화면이 나오며 기록·분석을 열 수 있다.
- [ ] 실제 LLM 요청이 성공하고 근거 발화가 붙은 요약·주제 분석이 저장된다.
- [ ] 앱 재진입 후에도 같은 기록·분석이 남아 있다.
- [ ] 웹에 같은 어르신의 같은 세션이 보이고 마지막 발화까지 일치한다.
- [ ] 웹에서 같은 세션의 LLM 일지 초안을 불러와 검토·수정·최종 저장하고 다시 열어 본문을 확인한다.
- [ ] 보호자 코드 요청을 담당자가 승인한다.
- [ ] 일지 공개 후 보호자 계정에서 동일한 본문을 확인한다.
- [ ] 화면 녹화 파일에 앱 출력 음성과 촬영자의 발화가 모두 들어갔는지 짧게 시험한다.

Realtime 구독에는 세션·분석·일지·공개·보호자 연결이 이미 포함돼 있다. 옛 문서의 '6종 미구독'을 현재 미구현으로 다시 분류하지 않는다. 라이브 이벤트 수신 여부는 리허설에서 확인하고, 실패 시 재조회와 비교해 원인을 구분한다.

근거: `apps/mobile/src/data/session-persistence.ts`, `apps/mobile/app/session/saved.tsx`, `apps/mobile/app/log/[id].tsx`, `packages/data/src/hooks/realtime.ts`, `apps/web/src/pages/caregiver/ConversationLogPage.tsx`.

## 조건부 수정·촬영 중 주의점

| 항목 | 확인 결과 | 촬영 판단 |
|---|---|---|
| 대화 요약만 공개 | 공개 UI는 session_summary를 생성하지만 `useMySharedContent`는 analysis 공개 ID만 조회하고 보호자 FeedPage도 analysis만 처리한다 | 일지 공개만 촬영하면 직접 차단 아님. 요약 단독 공개를 보여주려면 조회·피드·서버 공개 권한을 함께 수정/검증. 분석 전체 공개는 실제로 그 범위 공개를 의도할 때만 사용 |
| 앱 분석 조회 실패 | reads의 useLog/useAnalysis가 error 상태를 화면에 전달하지 않음 | 리허설에서 빈 분석·비활성 버튼이 생기면 우선 오류/재시도 표시 보강. 빈 화면을 정상 분석 완료로 취급하지 않음 |
| 분석 내용 기대치 | 관찰 지표는 기존 결정론 집계, LLM은 근거 발화가 붙은 요약·주제·일지 초안을 생성하도록 구현 | 실제 생성 성공을 확인한 뒤 촬영. 한 세션으로 장기 향상률이 채워질 것이라고 기대하지 않음 |
| 녹음 다시 재생 | 웹 대화 기록의 재생바는 '녹음 없음'. 저장된 음성의 재생은 미구현 | 웹에서는 텍스트 대화 내역을 촬영. 앱 현장 음성은 촬영 파일에 녹음 |
| 사진/음성으로 일지 작성 | 추가 Storage/STT 외부 경로를 사용 | 요구 장면에 필수 아니면 텍스트 입력으로 촬영. 사진을 넣으면 업로드·공개·보호자 표시까지 별도 리허설 |
| 웹 실행 환경 | 마지막 사용자 답변은 웹 미배포. 현재 배포 여부는 재확인하지 않음 | 같은 PC에서 로컬 웹으로 촬영할 수 있으므로 공개 배포 자체가 촬영 선행 개발은 아님. 실제 Supabase 연결은 필요 |

## 촬영 후로 미룰 개발

현행 기능을 정확히 소개하는 제한된 시연 기준이다. 출시 차단 판정은 그대로 유지한다.

- 시작·회수 중심 자동 대화 UI 및 T01 상태 규칙의 전체 I/O 연결.
- 상세 의미·사실 검증, 중단된 음성과 모델 맥락의 일치, 장시간/다중 인스턴스 운영.
- 상세 시간·원가 계측, 사용량·과금, 구독 화면.
- LLM 일지 품질 고도화, 독립 학습 데이터와 자체 모델 평가. 기본 실 API 초안 생성은 촬영 전 범위다.
- 녹음 영구 보관/웹 재생, 선택적인 사진 기능 확장.
- 스토어 공개 출시 준비와 나머지 R013 이후 감사 과제. R010은 계속 부분 해결이다.

이번 촬영 범위는 **현행 대화 조작→저장·실 LLM 분석→웹 전문 조회→실 LLM 일지 초안→담당자 최종 저장·공개→승인된 보호자 열람**이다. 새 자동 대화나 Clova 사용을 필수 장면으로 잡으면 해당 기능의 실제 연결 완료를 선행해야 한다.
