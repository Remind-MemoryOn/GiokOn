## N02/N08 자동 루프 연결 — 2026-09-20

`automatic.ts`는 한 연결의 시작·입력 채택·저장·응답·검증된 음성 재생·다음 청취를 직렬 실행한다. 같은 단계의 중복 입력을 거절하며 회수 뒤 늦은 응답을 폐기한다. 저장 성공과 재생 완료가 다음 청취의 조건이다. 위기/담당자 확인 권고는 어르신 입력과 안전 이벤트를 남기고 다음 모델 요청 없이 회수한다(이미 공급자에 스트리밍된 원음까지 소급 취소하지 않는다).

`useAutomaticConversation.ts`가 실제 앱 스토어·엔진·저장·마이크 권한·저장 버전 확인을 연결한다. 중계 모드 정상 UI는 시작/회수·저장이고 매 턴 확인 패널을 표시하지 않는다. 자동 입력은 담당자 확인 액션을 호출하지 않으며 모델 응답이 없을 때 로컬 AI 질문을 만들어 기록하지 않는다. 백그라운드/화면 이탈은 연결을 닫는다. 직접 Live의 기존 수동 경로는 유지한다.

실패 회귀(컨트롤러 8/스토어 2/저장 결과 2) 및 훅-실제 스토어 연결 3건 확인. 전체 508건(core 234/data 127/mobile 128/relay 19), 전체 typecheck·모바일 lint·copy/BOM/font/figma 통과. 현재 발화 종료는 기존 엔진의 1.6초 전사 정지 기준이며 PCM 기반 침묵/짧은 맞장구/무응답 개선은 다음 N08 작업이다. 일시정지 후 같은 세션 재개·재청취는 N10의 실제 전달 맥락 계약과 함께 이어 붙인다. 실기기/API/운영 적용 완료가 아니다.

## N08 기본 발화 경계 — 2026-09-20

중계 모드에 PCM RMS와 전사 도착 시각을 함께 보는 InputEndpoint를 연결했다. 일반 문장은 활동 후 3.5초, 3자 이하 응답은 6초 기다린다. 전사 없는 무활동 20초는 빈 입력으로 회수하며, 계속되는 잡음/발화도 60초 청취 상한에서 중단한다. 강제 상한은 완성 문장으로 제출하지 않는다. 시간은 단조 시계를 사용한다. 입력 청크 형식 오류와 회수 이후 콜백은 다음 턴으로 전달하지 않는다.

이 값들은 현장 검증 전 초기값이다. RMS는 사람 목소리/TV/잡음을 구별하는 VAD가 아니며 연속 잡음은 상한까지 청취를 유지할 수 있다. 강제 중단 전의 부분 입력 복구 및 공급자 전사 조각 누적/늦은 최종 전사는 후속 작업이다. 따라서 N08 전체 완료가 아니다. 직접 Live 수동 경로의 1.6초 정책은 유지한다.

검증: 신규 정책 7건·엔진 통합 5건 포함 전체 자동 테스트 520건(core 234/data 127/mobile 140/relay 19) 통과. 네이티브 의존성·운영 설정·DB 변경 없음. PCM 형식은 Google Live API capabilities의 16-bit little-endian 명세를 확인했다: https://ai.google.dev/gemini-api/docs/live-api/capabilities

## N08 전사 조각 손실 수정 — 2026-09-20

Live 입력 전사를 마지막 조각으로 덮어쓰던 엔진을 청취 단위 누적으로 수정했다. 공백·반복을 임의 교정/중복 제거하지 않는다. 청취 밖 입력은 무시하고 새 청취에서 초기화한다. 누적 4000자 초과는 잘린 문장을 저장하지 않고 중단한다. 중계도 개별 조각이 4000자를 넘으면 잘라 보내던 처리를 제거하고 연결을 종료한다.

변경 전 테스트에서 여러 조각으로 받은 ‘고향은 전주예요. 네. 네.’가 ‘네.’만 남음을 재현했다. 신규 회귀 3건 포함 전체 523건(core 234/data 127/mobile 142/relay 20) 통과. API의 serverContent는 incremental update이며 inputTranscription은 다른 메시지와 순서 보장이 없다(https://ai.google.dev/api/live). 따라서 이번 수정은 이미 수신한 조각 보존이며, 발화 끝의 모든 전사가 도착했다는 보장은 아니다. 늦은 최종 전사와 강제 중단 입력 복구는 다음 작업이다. 운영 배포/DB 변경/실제 공급자 호출 없음.
## N08 중단 입력의 담당자 확인 복구 — 2026-09-20

엔진 close 시 청취 중 이미 받은 전사를 onDraftInterrupted로 한 번만 전달한다. 자동 루프의 정상 입력 콜백과 다르며, 앱 훅은 현재 계정/세션/화면 범위에서 pendingStt에 보관한다. 정상 자동 진행에는 확인 패널이 없고 중단 입력이 있을 때만 확인 UI가 열린다. 종료 저장은 이 입력을 확인하거나 명시적으로 제외할 때까지 보류한다.

confirmRecoveredInput은 담당자가 확인한 문장만 caregiver_confirmed로 기록하고 presentedText/originalText와 입력 출처를 보존한다. 빈 확인·중복 확인은 거절하며, 안전 이벤트는 검사하지만 로컬 AI 응답을 만들어 기록하지 않는다. 긴 부분 입력은 편집 시 200자로 잘리지 않으며 스크롤 가능한 입력창에서 최대 4000자를 다룬다.

회귀 4건(엔진 중단 1, 스토어 확인 2, 실제 훅-스토어 연결 1) 포함 전체 527건(core 234/data 127/mobile 146/relay 20), 전체 typecheck·모바일 lint·copy/BOM/font/figma 통과. 운영/DB 변경 및 실기기 검증 없음. 현재 화면/메모리 안에서 이미 수신한 전사 복구이며 프로세스 종료 후 복구, 아직 공급자에서 오지 않은 전사, 일시정지 후 자동 재개는 후속이다.

## N09 종료 정리의 예외 격리 — 2026-09-20

청취 중 close의 native mic stop 예외가 공급자 소켓 종료와 부분 전사 복구를 건너뛰던 회귀를 수정했다. 소켓 참조를 먼저 해제하고 각 정리를 독립적으로 시도한다. 같은 엔진의 close 호출은 한 Promise를 공유한다. 취소된 연결 획득은 이미 진행 중인 네이티브 정리를 기다리지 않고 null로 끝나며 정리 책임은 기존 close 호출에 유지한다.

마이크 예외의 변경 전 실패/후 통과 및 콜백·재생 정리 오류/중복 종료 회귀 총 2건 추가. 전체 529건(core 234/data 127/mobile 148/relay 20) 통과. N09 전체 완료는 아니며 네이티브 unload 무한 대기, 일반 stopListening의 정리 예외, 오디오 라우트/전화 등은 후속이다. 늦은 전사의 최종 경계는 공급자 메시지 순서 제약을 고려해 N10 맥락 계약과 함께 이어서 다룬다. 운영/DB 변경 없음.
## N09 재생 해제 무한 대기 경계 — 2026-09-20

player의 unload와 임시 파일 정리에 5초 대기 상한을 추가했다. timeout은 native 취소 성공이 아니므로 미완료 cleanup Promise를 유지하며 다음 재생도 그 정리를 통과해야 시작된다. 늦게 unload가 성공하면 문을 다시 열지만 unload가 명시적으로 실패한 경우에는 프로세스 수명 동안 재생을 거절한다. 기존 엔진의 종료 오류 경로로 전달된다. 정상 완료·중단·늦은 로드 정리도 동일 경계를 사용한다.

멈춘 unload의 수정 전 timeout 재현 후 회귀 2건 추가. 전체 531건(core 234/data 127/mobile 150/relay 20) 통과. 네이티브 의존성 변경/실기기/운영/DB 변경 없음. native createAsync/setAudioModeAsync/파일 쓰기가 반환되지 않는 경우와 실제 오디오 하드웨어 종료 검증은 남아 있다. timeout으로 기기의 소리가 강제로 멈췄다고 주장하지 않는다.
## N09 일반 청취 중지 실패 — 2026-09-20

stopListening의 native stop 실패는 빈 반환과 연결 종료로 처리하며 받은 전사는 부분 입력 확인 콜백으로 보낸다. 정상 확정 콜백은 호출하지 않는다. 실제 설치 모듈을 감싼 어댑터도 실패를 삼키지 않고 리스너 정리 후 호출자에게 전파한다. 중지 상태가 불확실해진 어댑터는 프로세스 재실행 전 다시 시작할 수 없다.

엔진 신규 회귀 1건·기존 설치 모듈 회귀 강화 모두 수정 전 실패/후 통과. 전체 532건(core 234/data 127/mobile 151/relay 20) 통과. 이 수정으로 기기 마이크가 반드시 종료됐음을 증명하는 것은 아니며 실제 기기 확인은 남는다. 운영/DB/네이티브 의존성 변경 없음.

## N05 운영 종료·readiness — 2026-09-20

신규 연결 차단 drain과 /readyz를 추가했다. shutdown은 각 relay 취소 함수를 직접 호출해 합성 취소·공급자 종료·내부 세션 점유 해제를 수행한 후 HTTP/WebSocket 서버 종료를 기다린다. 반복 종료는 같은 Promise를 공유하며 5초 강제 정리 경계가 있다. /healthz는 공급자 상태와 무관한 프로세스 생존만 의미한다.

## N07 Clova 취소·본문 제한 — 2026-09-21

공급자 fetch/reader가 abort에 응답하지 않더라도 앱 연결 취소 또는 15초 요청 제한이 합성 호출을 종료하도록 Promise 경계를 추가했다. 요청 취소 신호와 제한 시간을 본문 읽기까지 동일하게 사용한다. 늦게 도착한 응답은 사용하지 않고 body cancel을 요청한다. reader.cancel이 반환되지 않아도 종료를 막지 않는다. 실제 공급자가 이미 처리한 데이터를 소급 취소하는 것은 아니다.

429는 CLOVA_RATE_LIMIT, 5xx는 CLOVA_UNAVAILABLE, 나머지 비정상 응답은 CLOVA_FAILED로 분류하며 오류 본문을 전달/로그하지 않는다. 자동 재시도로 과금을 늘리지 않고 기존 중계 종료 흐름으로 간다. WAV는 전체 RIFF 길이뿐 아니라 마지막 청크 경계도 검사하여 뒤의 불완전 데이터를 거절한다.

회귀 7건(취소/정리 정체 2, RIFF 1, HTTP 상태 3, 본문 제한 시간 1) 추가. 중계 전체 29건·타입 검사·BOM 통과. 앱/공통 소스 변경 없음. 실제 Clova 429/음질·속도·개인 사실 의미 검증·운영 배포는 미수행이며 N06/N07 전체 완료가 아니다.
## N10 턴별 재생 관측 런타임 — 2026-09-21

자동 루프가 playTurn 결과를 앱 스토어의 playbackByTurnId에 기록한다. 값은 정확한 질문 text, completed/interrupted/empty, 앱 관측 시각이다. 어르신이 실제로 듣거나 이해했다는 증거는 아니다. 훅은 출력 채택 당시 턴 ID와 문장을 캡처하며 스토어는 해당 AI 턴/텍스트가 일치할 때만 반영한다. 완료 관측이 있는 동일 문장은 이후 실패로 소급 미전달 처리하지 않는다. 기록이 없는 턴은 완료로 추정하지 않는다.
