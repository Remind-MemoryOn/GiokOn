# 자동 대화 완성 실행 기록 — 2026-09-20

목표: 사용자가 요청한 자동 대화 완성 목록 전체(T03b, N02/N08, 발화 종료, N09, N10, N06/N07, N05)를 구현한다. 각 테스크는 실패 회귀→구현→검증→기록→커밋 순서로 진행한다. 기존 설계는 voice-development-tasks.md와 voice-ai-personalization.md를 따른다.

운영 DB 보안 감사는 제외한다. 기능용 저장 계약은 개발 가능하지만 운영 적용·외부 자격 증명·실기기 검증은 사용자 작업으로 구분한다. .env와 민감 파일은 읽지 않는다. 외부 작업 선행 없이는 개발할 수 없는 항목은 보류한다. 외부 작업을 뒤로 미룰 수 있으면 로컬 구현·검증을 끝내고 요청한다. 부분 완료를 전체 목표 완료로 판정하지 않는다.

## N09a 검증 — 2026-09-20

마이크 시작 요청에 청취 세대를 부여해 권한 검사 대기 중 중단된 요청과 이전 청취의 늦은 오디오를 폐기한다. 한 청취의 확정 콜백은 한 번만 발생한다. native playAsync가 미완료여도 중단·완료·90초 제한이 호출자를 정리하도록 변경했다. 실제 장치의 unload 자체가 멈추는 문제를 해결했다고 주장하지 않는다.

추가 회귀 5건 변경 전 실패/후 통과. `pnpm -r test` 482건(core 234/data 116/mobile 113/relay 19), `pnpm -r typecheck`, `pnpm -r lint`, copy/BOM/font/figma 통과. 실기기·외부 API·운영 변경 없음. N09 전체(전화/Bluetooth/백그라운드 등)는 진행 목록에 남는다.

## T03b 검증 — 2026-09-20

새 계약 SQL·매퍼·스토어 입력 출처 테스트의 변경 전 실패를 확인했다. PostgreSQL 16 임시 컨테이너에 전체 53개 마이그레이션 적용 후 기존 DB 회귀와 신규 transcript_provenance.sql 통과. 출처 왕복·서버 확인자/시각·교정 이력·멱등 재시도·구버전 호환을 확인했다. 전체 492건·typecheck·lint·copy/BOM/font/figma 통과 후, AI/어르신 혼합 bulk payload의 컬럼 일치 회귀 1건을 추가했다(최종 data 127건). 적용·호환·롤백은 `docs/runbooks/transcript-storage-rollout.md`. 운영 DB 적용 요청은 자동 기능 실사용 전 필요하며 현재 수행하지 않았다.

## N02/N08 자동 루프 연결 — 2026-09-20

`automatic.ts`는 한 연결의 시작·입력 채택·저장·응답·검증된 음성 재생·다음 청취를 직렬 실행한다. 같은 단계의 중복 입력을 거절하며 회수 뒤 늦은 응답을 폐기한다. 저장 성공과 재생 완료가 다음 청취의 조건이다. 위기/담당자 확인 권고는 어르신 입력과 안전 이벤트를 남기고 다음 모델 요청 없이 회수한다(이미 공급자에 스트리밍된 원음까지 소급 취소하지 않는다).

`useAutomaticConversation.ts`가 실제 앱 스토어·엔진·저장·마이크 권한·저장 버전 확인을 연결한다. 중계 모드 정상 UI는 시작/회수·저장이고 매 턴 확인 패널을 표시하지 않는다. 자동 입력은 담당자 확인 액션을 호출하지 않으며 모델 응답이 없을 때 로컬 AI 질문을 만들어 기록하지 않는다. 백그라운드/화면 이탈은 연결을 닫는다. 직접 Live의 기존 수동 경로는 유지한다.

실패 회귀(컨트롤러 8/스토어 2/저장 결과 2) 및 훅-실제 스토어 연결 3건 확인. 전체 508건(core 234/data 127/mobile 128/relay 19), 전체 typecheck·모바일 lint·copy/BOM/font/figma 통과. 현재 발화 종료는 기존 엔진의 1.6초 전사 정지 기준이며 PCM 기반 침묵/짧은 맞장구/무응답 개선은 다음 N08 작업이다. 일시정지 후 같은 세션 재개·재청취는 N10의 실제 전달 맥락 계약과 함께 이어 붙인다. 실기기/API/운영 적용 완료가 아니다.

## N08 기본 발화 경계 — 2026-09-20

중계 모드에 PCM RMS와 전사 도착 시각을 함께 보는 InputEndpoint를 연결했다. 일반 문장은 활동 후 3.5초, 3자 이하 응답은 6초 기다린다. 전사 없는 무활동 20초는 빈 입력으로 회수하며, 계속되는 잡음/발화도 60초 청취 상한에서 중단한다. 강제 상한은 완성 문장으로 제출하지 않는다. 시간은 단조 시계를 사용한다. 입력 청크 형식 오류와 회수 이후 콜백은 다음 턴으로 전달하지 않는다.

이 값들은 현장 검증 전 초기값이다. RMS는 사람 목소리/TV/잡음을 구별하는 VAD가 아니며 연속 잡음은 상한까지 청취를 유지할 수 있다. 강제 중단 전의 부분 입력 복구 및 공급자 전사 조각 누적/늦은 최종 전사는 후속 작업이다. 따라서 N08 전체 완료가 아니다. 직접 Live 수동 경로의 1.6초 정책은 유지한다.

검증: 신규 정책 7건·엔진 통합 5건 포함 전체 자동 테스트 520건(core 234/data 127/mobile 140/relay 19) 통과. 네이티브 의존성·운영 설정·DB 변경 없음. PCM 형식은 Google Live API capabilities의 16-bit little-endian 명세를 확인했다: https://ai.google.dev/gemini-api/docs/live-api/capabilities

## N08 전사 조각 손실 수정 — 2026-09-20

Live 입력 전사를 마지막 조각으로 덮어쓰던 엔진을 청취 단위 누적으로 수정했다. 공백·반복을 임의 교정/중복 제거하지 않는다. 청취 밖 입력은 무시하고 새 청취에서 초기화한다. 누적 4000자 초과는 잘린 문장을 저장하지 않고 중단한다. 중계도 개별 조각이 4000자를 넘으면 잘라 보내던 처리를 제거하고 연결을 종료한다.

변경 전 테스트에서 여러 조각으로 받은 ‘고향은 전주예요. 네. 네.’가 ‘네.’만 남음을 재현했다. 신규 회귀 3건 포함 전체 523건(core 234/data 127/mobile 142/relay 20) 통과. API의 serverContent는 incremental update이며 inputTranscription은 다른 메시지와 순서 보장이 없다(https://ai.google.dev/api/live). 따라서 이번 수정은 이미 수신한 조각 보존이며, 발화 끝의 모든 전사가 도착했다는 보장은 아니다. 늦은 최종 전사와 강제 중단 입력 복구는 다음 작업이다. 운영 배포/DB 변경/실제 공급자 호출 없음.
