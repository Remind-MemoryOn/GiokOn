# 실 API 시연 구현 진행

사용자 승인: 실 LLM API를 연결해 앱 대화·분석→웹 일지 초안·최종 확인·공개→보호자 열람까지 시연 가능한 상태로 만든다. 전체 출시 개발은 촬영 이후로 미룬다. `.env` 등 민감 파일 접근 금지 유지.

## 인수 조건

2026-09-14 사용자 후속 지시: 실제 API·실기기·웹/보호자 종단 검증은 사용자가 직접 진행한다. 이번 개발 인계 범위는 구현·자동 검증·현재 변경 커밋이며, 아래 실환경 인수 조건은 사용자 확인 체크리스트로 유지한다. 시연 준비 완료로 자동 판정하지 않는다.

- 실제 로그인·기관/배정·동의 검증을 거친 서버만 공급자 API를 호출한다. 서버가 저장된 세션 기록을 조회하며 다른 어르신의 기록이나 클라이언트가 만든 전사를 그대로 신뢰하지 않는다.
- 대화 시간·횟수·응답률은 기존 결정론 계산을 유지한다. LLM은 핵심 요약·주제별 내용·회상 활동 일지 초안을 생성한다.
- 결과는 형식·길이·근거 발화 ID/실제 인용·비의료 표현을 검사한다. 실제 인용 확인은 의미 전체의 사실성을 보증하지 않으므로 담당자 최종 검토를 유지한다.
- 앱 분석 화면과 웹에서 LLM 결과를 읽고 생성 실패를 확인·재시도할 수 있다. 생성되지 않은 결과를 LLM 완료로 표시하지 않는다.
- 웹은 완료된 세션을 선택해 일지 초안을 불러오고 수정·최종 저장·공개한다. 초안 생성만으로 공개하지 않는다.
- 담당자와 보호자 계정의 코드 연결·승인을 포함해 동일 일지가 열리는지 검증한다.
- 운영 함수 배포·실제 공급자 호출과 앱/웹 종단 검증을 완료해야 목표 완료로 판정한다. 단위 테스트나 로컬 어댑터만으로 완료 판정하지 않는다.

## 실행 순서와 현재 상태

1. [x] 공유 생성 응답 계약 및 근거 검증기. `generated-session.ts`와 회귀 6건·core 타입 검사 통과.
2. [x] 서버 코드 구현: Gemini REST, 종료 세션·동의·시연 계정 검사, 응답 크기/시간 제한, 근거 검증, 원본 해시·분석 revision 확인, 기존 JSON에 저장/재사용. 실호출은 6번에서 판정.
3. [x] 모바일 분석 화면 진입 시 생성·상태/실패/재시도·주제별 근거 표시 구현. 설치 앱 검증은 7번에서 판정.
4. [x] 웹 세션 선택→초안 미리보기→명시적 본문 적용→기존 저장/공개 경로 배선. ai_draft 출처 유지. 합성 API 브라우저 시험 통과, 실제 저장·공개는 7번에서 판정.
5. [x] 자동 회귀·빌드 및 일지 공개 경로 코드 점검. 요약 단독 공개 문제는 일지 공개 시연을 직접 차단하지 않아 후속 범위로 유지한다. 실제 공개 동작은 7번에서 확인한다.
6. [ ] 최초 함수 배포·소스 대조와 설정 이름 존재 확인 완료. 실제 API 호출은 사용자가 검증한다. 현재 v5 소스 대조는 별도 미확인이다.
7. [ ] 설치 앱·웹·보호자 종단 리허설 — 사용자 직접 진행으로 인계했다.

## 개발 인계 및 로그인 후속 수정

- 개발 커밋: `e2d2ed4`(LLM 분석·일지 초안), `389726c`(로그인 전환 회귀 수정). 원격 푸시는 수행하지 않았다.
- 로그인 정체는 R008 커밋 `aa1eede`에서 추가한 최신 조회만 채택하는 처리와 개별 조회 반환값으로 화면을 이동하던 코드의 충돌로 재현됐다. 최종 인증 상태를 구독해 이동하도록 수정했다. 역할·기관 검사는 유지한다.
- 수정 전 회귀 실패, 수정 후 모바일 97건·타입·lint·copy/BOM/font/figma 및 Android JS export 통과. 실제 계정 로그인 성공을 대신하는 증거는 아니다.
- 사용자 검증 순서: 최신 앱 재로드→로그인→대화 종료·저장→AI 분석→웹에서 같은 세션 초안 적용·최종 저장→승인된 보호자에게 공개→동일 본문 확인. 새 오류가 있으면 발생 단계와 오류 문구로 후속 진단한다.

## 연결 설계

기존 Supabase의 서버 Gemini 인증을 재사용한다. Live 음성 모델과 보고서 생성용 텍스트 모델은 구분한다. 보고서 호출은 종료된 세션에 대해 `can_process_profile`과 세션 조회 권한을 검사한다. `can_process_session`은 active 전용이므로 종료 후 보고서의 인가 함수로 사용하지 않는다.

LLM 출력 계약은 summary/topics/journal이며 각 문장에는 Elderly 발화 ID와 실제 인용이 필요하다. 계산 지표를 LLM 출력에 포함시키지 않는다. 기존 session_analyses JSON과 care_journals의 편집/최종 공개 구조를 활용할 수 있는지 서버 구현에서 검증한다. 생성 메타데이터에는 모델·생성 시각·원본 세션 출처를 남긴다.

## 2026-09-14 검증 및 운영 기록

- 커밋 전 모노레포 전체 테스트 452건 통과(core 234, data 114, mobile 90, voice-relay 14). 전체 타입 검사 통과.
- data/mobile/web 타입 검사, mobile/web lint, copy/BOM/font/figma/design 통과. 웹 빌드는 `envDir:false`로 실행했다.
- Android/iOS JS export 각각 성공(약 5.85MB). `EXPO_NO_DOTENV=1`로 실행했으며 두 결과의 metadata.json도 확인했다. 이는 네이티브 설치·마이크·실제 API 연결 성공을 보증하지 않는다.
- `apps/web/scripts/report-flow-smoke.mjs`: 실제 브라우저에서 세션 선택·API 요청·초안 미리보기·사용자 명시적 교체·근거 표시 통과. 502 생성 실패·재시도·Escape 취소에도 기존 작성 본문이 보존되는 것을 추가 확인했다. 합성 API 응답이며 실제 Gemini 성공을 뜻하지 않는다.
- CLI로 서울 `ufkbzpdjomtmxjipmwub`의 `session-report` v1 배포. ACTIVE·verify_jwt=true, 인증 없는 실제 HTTP 요청 401 확인. MCP로 배포 파일 4종을 읽어 로컬과 내용 일치를 확인했다. CLI download는 core 외부 경로 추출 제한으로 실패해 읽기 전용 MCP 조회로 대체했다.
- 서버 `GEMINI_API_KEY` 등록 여부만 확인했고 값은 읽지 않았다. 보고서 모델 설정 `GEMINI_REPORT_MODEL=gemini-2.5-flash`를 CLI로 등록했다. Live 모델 설정은 변경하지 않았다. 공식 모델 폐기 문서상 shutdown 미공고 확인: https://ai.google.dev/gemini-api/docs/deprecations
- 사용자 등록 완료 보고 후 CLI로 `GEMINI_API_KEY`·`GEMINI_REPORT_MODEL`·`REPORT_ALLOWED_USER_IDS` 세 이름의 존재를 확인했다. 값은 읽거나 출력하지 않았으므로 키 유효성·모델명·담당자 UUID 일치는 실제 호출로 확인해야 한다. 같은 시점 함수는 v5 ACTIVE·verify_jwt=true였다. 앞선 v1 소스 대조 결과를 v5 검증으로 간주하지 않는다. 실환경 검증은 사용자 진행이다.
- 호출 제한은 인스턴스당 사용자 분당 3회와 세션별 실행 잠금이다. 다중 인스턴스에서의 전역 과금 상한은 아니다. 시연 계정 허용 목록·저장 결과 재사용을 함께 사용하며 일반 운영 개방으로 취급하지 않는다.

실제 공급자 호출·설치 앱·웹→보호자 저장/공개 리허설은 아직 미완료다. 문서상 과거 규칙 기반 구현 이력은 그대로 보존한다.
