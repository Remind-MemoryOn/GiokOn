# A+B+C 음성 지연 개선 구현

2026-10-17 사용자 승인: 공급자 원음 재생 대기 분리(A), 검증 후 TTS 스트리밍(B), 간결한 답변(C)을 적용하고 테스트한다. 발화 종료 1초는 유지한다.

## 계약

- v5 앱만 스트리밍 협의. v1~4 호환 경로 유지. `relayStream {turnId,text}` → `relayAudio {turnId,index,data}` → `relayAudioEnd {turnId}`.
- 전체 생성문 검증 후 TTS 시작, PCM24k 형식·크기·순서 검증. 원음 전달 금지.
- 앱은 첫 청크에 응답을 채택·저장하고 같은 AEC 경로에서 재생. 완료는 명시적 스트림 끝과 실제 재생 끝 모두 확인해야 한다. 중단은 interrupted이며 남은 합성을 취소한다.
- 공급자 생성 완료와 턴 종료를 분리. 이전 공급자 턴 종료가 다음 응답으로 오인되지 않도록 다음 입력에 순서 장벽을 둔다. 대기·버퍼는 제한하고 회수/위기/권한 상실 시 폐기한다.
- 응답은 짧은 공감(필요할 때만)과 질문 하나, 기본 1~2문장·80자 이내를 지시. 어르신 입력을 잘라내지 않는다.

## 검증 및 상태

- ⏳ 스트리밍 공급자 SSE 회귀: 분할 프레임·오류·잘린 끝·취소·미검증 텍스트·오디오 크기/형식.
- ⏳ 중계: 생성 완료 후 첫 음성 전달, 늦은 이전 턴 완료/새 입력, 중단/위기/원격 회수/10분 상한·구버전 호환.
- ⏳ 앱·네이티브: 청크 공백은 완료 아님, 실제 재생 끝, 끼어들기, 실패/늦은 콜백/백그라운드 정리.
- ⏳ 타입·린트·앱/중계 테스트·수동 게이트·Android/iOS 번들·네이티브 빌드.
- ⏳ 중계 배포→새 APK 설치→사용자 실기기 짧은/긴 답변·끼어들기·실제 첫 음성 지연 확인. 검증 전 3초 달성 주장 금지.
