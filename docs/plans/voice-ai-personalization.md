# 기억온 음성 이해·개인화 AI 전환 계획

## 1. 검토 결론과 적용 범위

2026-09-12 사용자 확정 설계다. 초기 입력·대화는 Gemini Live, 출력은 검증 텍스트의 Clova TTS이며 장기 대화 모델 목표는 Qwen3.5-9B다. 9월 11일 일반 오디오 API 우선·Live 비교용 결정을 대체한다. **초기에는 Gemini 오디오 직접 입력과 프롬프트·명시적 대화 정책으로 운영하고, 적법하게 확보하고 검수한 데이터로 Whisper와 공개 가중치 대화 모델을 각각 특화하는 방향을 조건부 채택한다.** 파인튜닝만으로 네 가지 문제가 완전히 해결된다고 가정하지 않는다. 한국어 어르신 실음성 평가·안전·데이터 권리·운영비 게이트를 통과한 구성요소만 교체한다.

이 문서는 앱 회상 대화의 신규 계획 기준이다. `PLAN.md` M7·M12, `tech.md`, `ai-safety.md`와 함께 읽는다. 7월 MVP 문서의 mock 출시·키만 넣으면 무변경 전환과 9월 감사 문서의 Live 전용 출시 가정은 이 계획으로 대체한다. **설계 반영이며 코드 구현·실 API 검증·배포 완료를 뜻하지 않는다.** 웹 요양일지의 CLOVA STT와 웹 관리/모바일 대화 역할 경계, 확정 Figma 디자인은 유지한다.

| 제안 | 판단 | 보완한 결정 |
|---|---|---|

| 부정 감정의 다른 의도 구분 | 필수 | 음성 인식 불확실성·부정/인용/과거·현재 위험을 분리하고 애매하면 확인 |

## 2. 기술 근거와 확인 한계

Gemini의 일반 오디오 이해 기능은 오디오를 입력받아 텍스트를 생성하며, 전사와 내용 해석에 사용할 수 있다. 이것은 순수한 음향 전사 정답을 보장한다는 뜻이 아니다. Live는 별도의 실시간 대화 경로다. 따라서 “Audio-to-Text”를 특정 모델명이나 Live의 텍스트 모드와 같은 뜻으로 쓰지 않는다. [Google 오디오 이해 문서](https://ai.google.dev/gemini-api/docs/audio)

현재 저장소의 `gemini-3.1-flash-live-preview`는 공식적으로 audio-to-audio 모델이며 **Structured Outputs를 지원하지 않는다**. 출력 전사가 존재해도 임의 JSON 스키마 보장과 다르다. 해당 버전의 proactive audio/affective dialogue도 미지원이다. 오디오 감정 이해를 인지능력 점수나 위기 판정 근거로 확정하지 않는다. 모델 ID·API 버전·지원 기능은 도입 시 다시 검증하고 버전을 기록한다. [Google 모델 사양](https://ai.google.dev/gemini-api/docs/models/gemini-3.1-flash-live-preview)

Whisper의 다국어 ASR 파인튜닝 절차는 공개되어 있다. 그러나 한국어 고령자·방언·말운동 장애·녹음 환경에 대한 이 서비스의 개선율은 아직 측정되지 않았다. 중국어 비전형 발화의 화자 적응 연구는 연구 가능성의 근거이며 한국어 성능 보증이 아니다. [Hugging Face 학습 가이드](https://huggingface.co/blog/fine-tune-whisper), [Perceiver-Prompt 연구](https://arxiv.org/abs/2406.09873)

Whisper 연구에서는 무발화 구간의 환각과 긴 비발성 구간을 가진 화자의 불균형한 오류가 보고됐다. 따라서 침묵을 문장으로 채우는 오류는 WER 개선과 별도로 검증한다. 해당 결과를 모든 최신 체크포인트에 동일한 오류율로 적용하지 않는다. [Careless Whisper](https://arxiv.org/abs/2402.08021), [비음성 환각 연구](https://arxiv.org/abs/2501.11378)

Ollama는 외부에서 학습한 모델/어댑터를 가져와 실행한다. 학습 기반 모델과 가져오는 어댑터의 일치, 지원 아키텍처·형식 확인이 필요하다. 모델 라이선스와 상용 사용·배포 조건은 Ollama의 라이선스와 별개로 검토한다. [Ollama Import](https://docs.ollama.com/import)

의사소통·감각 문제를 고려해야 한다는 NICE 권고는 지원 방식 설계의 참고 근거다. 여기서 제안하는 지원 모드는 임상 척도도, 해당 지침의 검증된 분류 체계도 아니다. NICE 본문은 이번 직접 접근에서 403으로 확인 범위가 제한돼 세부 권고를 임상 근거로 확장하지 않았다. [NICE NG97](https://www.nice.org.uk/guidance/ng97/chapter/Recommendations)

## 3. 초기 서비스 구조

### 3.1 우선 구현: Gemini Live 대화와 검증 텍스트의 Clova 출력

```text
담당자 생애정보·세션 설계 → 시작 지원 → 어르신 음성 직접 Gemini Live 입력
  → 프롬프트·개인 맥락에 따른 대화 진행 / 필요한 경우 어르신에게 재확인
  → 출력 전사 수신 → 서버 의미·안전 검증
  → 검증된 문장만 Clova TTS → 앱 재생 → 다음 청취
  → 중단/종료 → 담당자 회수·사후 확인 (예외에는 담당자 개입)
```

매 턴 담당자 확인은 목표 운영의 필수 단계가 아니다. 자동 턴 경계·긴 생각 시간·중단·오류 종료·도움 요청을 설계한다. 불명확한 말은 짧게 어르신에게 확인하고 해소되지 않으면 휴식/담당자 경로를 사용한다. 교정·취소로 무효화된 응답과 음성은 폐기한다. 실제 단독 사용 가능 범위는 아직 검증하지 않았다.

Live의 출력 전사·오디오 일치를 보장하지 않으며 Structured Outputs 지원을 전제하지 않는다. 서버 검증 실패·전사 누락 때 원본 Gemini 음성을 재생하지 않는다. Clova 호출 실패는 검증된 대체 문장 또는 종료 안내로 처리하고, 생성 음성 보관·재사용은 공급자 계약 확인 전 기능으로 약속하지 않는다. 웹 일지의 CLOVA STT는 별개다.

서버는 세션 소유·기관·배정·동의·상태·사용 한도를 검사한다. 앱 직접 연결의 이미 열린 공급자 연결은 DB 변경만으로 강제 종료할 수 없다는 R010 제한을 유지한다. 매 전송·연결 수명을 서버에서 통제할 중계/실행 환경을 설계해야 하며, Edge Function의 장시간 연결 적합성을 전제하지 않는다. 새 함수·중계·Clova 배선은 아직 미구현이다.

### 3.2 현재 코드와 목표의 차이

현재 Live client/engine/talk 화면에는 원음 전송, 수동 턴 경계, 전사 확인·수정 및 확정 턴 진행, PCM 재생 가드가 있다. 원음을 이미 처리하므로 '현재 모델은 확정 텍스트만 본다'고 단정하지 않는다. 기존 확인 패널 중심 상태 전이와 음성 재생 경로를 변경해야 한다. 일반 오디오 이해 API는 향후 비교 후보일 수 있지만 초기 주 경로가 아니다.

Live 누적 맥락의 반복 과금, 출력 전사 비용, 재생하지 않는 생성 음성, Clova 글자 수와 Application 기본료를 계측한다. 분당 요금만으로 총원가를 계산하지 않는다. 기관 구독·포함량은 미확정이며 무제한 대화를 전제하지 않는다. 구현 작업과 인수 조건은 [개발 실행안](business-plan-development-delta.md) D1~D7을 따른다.

### 3.3 네 가지 문제의 초기 처리

**발음·사투리:** 작은 음량, 주변 TV, 겹침 발화, 청력 문제와 발음 자체를 구분한다. VAD는 긴 생각 시간과 짧은 휴지를 발화 종료로 오인하지 않도록 기기별로 측정한다. 난해한 구간을 표준어로 억지 복원하지 않는다. `transcriptRaw`, `transcriptAccepted`, `unclearSpans`, `correctionSource`를 구분하는 계약을 설계하고 인식 불가 값은 null로 둔다. 모델이 제공하지 않는 신뢰도 숫자는 만들지 않는다. 위험 단어·이름·관계처럼 후속 행동을 바꾸는 해석은 짧게 확인한다. 반복 확인으로 피로해지면 사람 입력이나 휴식으로 전환한다.

**인지 상태에 맞는 진행:** 의료적 인지능력·치매 단계·MMSE 점수를 음성으로 추정하지 않는다. 초기에는 요양보호사가 의사소통 선호, 청력·보청기, 피로, 반응 대기, 선호/회피 주제를 확인한다. 외부 전문가 평가가 적법하게 제공된 경우 출처·평가일과 함께 참고할 수 있으나 자체 진단으로 재해석하지 않는다. `consents.capacity`는 동의 기록용이며 대화 난이도 점수로 재사용하지 않는다.

| 지원 모드(설계상 명칭) | 대화 방식 | 변경 기준 |
|---|---|---|
| 자유 회상 | 익숙한 소재에 열린 질문 하나 | 이야기 흐름이 유지되고 계속하고 싶어 함 |
| 단서 지원 | 짧은 문장, 확인된 사진·장소 단서, 필요 시 쉬운 선택 | 질문을 다시 요청하거나 이해에 도움이 필요함 |
| 충분한 지원·휴식 | 한 번에 한 생각, 긴 대기, 질문 부담 낮추기·휴식 선택 | 피로·불편·반복 미이해 또는 본인 요청 |

지원 모드는 고정 등급이 아니다. 세션 내에서 한 단계씩 조절하고 이유·관찰 시점·담당자 변경을 기록한다. 대답이 짧거나 STT가 실패했다는 이유만으로 지원 수준을 올리지 않는다. 음질·청력·통증·피로 등 대안을 먼저 확인하며, 동의성 맞장구를 이해 증거로 단정하지 않는다. 어르신의 중단 의사는 언제든 우선한다. 장기 추세도 관찰 자료일 뿐 인지 개선율로 표시하지 않는다.

**다른 의도의 부정 표현:** 감정의 부정성과 긴급 위험을 다른 축으로 다룬다. 발화 주체, 현재/과거, 인용, 부정, 관용 표현, 주변 맥락, 전사 불명확성을 함께 본다. 슬픔은 공감과 계속/전환 선택의 대상이다. 명백한 현재 위험은 확인 질문으로 지연시키지 않고 사람이 즉시 개입한다. 모호한 위험은 확인 대기 상태를 유지하고 짧은 확인 및 담당자 알림으로 연결한다. 무응답·모순·해소되지 않은 불확실성은 임의의 ‘안전’으로 닫지 않는다.

**개인별 의미:** 승인된 개인 의미 사전을 기관·어르신 범위로 조회한다. 예를 들어 ‘학교’가 과거 일터를 가리킬 수 있다는 사례는 테스트용 가정일 뿐 실제 프로필 값으로 넣지 않는다. 맥락별 복수 의미를 허용하고, 한 번의 모델 추정으로 전역 매핑을 만들지 않는다. 해당 세션에서 본인이 명확히 한 의미를 우선하고 장기 저장에는 확인 근거가 필요하다. 개인 사전도 명백한 위험을 무시하는 예외 목록으로 사용할 수 없다.

## 4. 안전 정책의 변경 경계

현재 `packages/core/src/safety.ts`는 구 단위 사전과 보수적 위험 판정, `prompt.ts`는 안전 지침, `conversation.ts`는 진행 규칙을 갖고 있다. 기존 문서의 결정론/모델 위험 OR 결합과 부정 문맥 위기 유지가 오탐을 늘릴 수 있다. **이 문서만으로 해당 코드가 변경된 것은 아니며, 기존 가드를 먼저 삭제하지 않는다.**

새 목표 상태는 `continue / clarify / watch / urgent / stop`처럼 **행동**을 분리하는 것이다(제안 계약, 현재 DB enum 아님). `urgent`는 즉시 담당자 호출과 신뢰 문구를 사용한다. `clarify/watch`는 근거와 불확실성을 남기고 사람에게 전달한다. 명확한 긴급 신호는 하한 규칙으로 유지하며, 애매한 사전 매칭은 새 문맥 평가의 후보로 바꾼다. 기존 일괄 OR 정책의 완화는 독립 평가셋에서 미탐과 오탐을 함께 확인하고 담당 안전 책임자가 승인한 뒤 출시한다.

평가 사례는 음식 ‘죽’, 관용 표현, 명시적 부정, 과거 타인 인용, 현재 위험, 돌봄 제공자에 의한 학대 가능성, 의도와 반대인 STT 오인식, 무응답을 포함한다. 학대가 의심되면 지목된 돌봄 제공자에게만 통지하지 않는 별도 책임자 경로가 필요하다. 확인 버튼을 눌렀다는 사실(`acknowledged`)과 위험이 해소됐다는 판정(`resolution`)을 구분한다. 오탐 정정은 원 이벤트를 지우지 않고 사유·담당자·시각을 추가한다.

알림 미확인·네트워크 실패·담당자 부재의 대체 연락과 현장 대응 책임을 정한다. 이 서비스는 상시 응급 감시나 의료 판단을 보장하지 않는다. AI 출력은 재생 전에 비의료·모욕·기억시험·사실 날조를 검증하고, 실패하면 중립적 재확인 또는 사람 연결로 끝낸다.

## 5. 개인화 데이터와 기록 설계

다음은 **신규 설계 후보**다. 현재 테이블에 이미 존재한다고 가정하지 않으며 DB 마이그레이션·타입·RLS·앱/웹 계약 설계 후 구현한다.

| 데이터 | 필수 근거·속성 | 사용 제한 |
|---|---|---|
| 의사소통 프로필 | 선호 질문 방식·대기·청취 설정, 설정자·근거·갱신일 | 임상 점수/동의능력과 분리 |
| 개인 의미 사전 | 표현, 맥락, 의미 후보, 원 기록, 확인자·확인일, 상태·버전 | 승인 정보만 장기 조회, 수정/철회 가능 |
| 턴 해석 | 원전사·채택 전사·불명확 구간, 모델/프롬프트 버전, 교정 출처 | 모델 추정과 사람 확인을 구분 |
| 지원 변경 | 이전/이후 모드, 이유가 된 턴, 확인자, 적용 기간 | 새로운 세션의 영구 등급으로 자동 승계 금지 |
| 안전 검토 | 후보 위험·맥락·대응, 확인/정정/해결 이력 | 관찰과 판단을 구분, 원 기록 보존 |
| 학습 자료 계보 | 원음/전사 ID, 동의 범위·버전, 출처·권리, 검수자, 데이터셋/모델 버전 | 운영 저장과 학습 사용은 별도 권한 |

최소 정보만 서버에서 조회해 프롬프트에 제공한다. 이름·가족사 전체를 매 요청 보내지 않는다. 연대기·개인 사전·전사에 포함된 지시문은 신뢰할 수 없는 데이터로 취급하며 시스템 안전 지침을 덮어쓰지 못하게 한다. 검색/캐시 키에도 기관·어르신·버전을 포함하고, 다른 기관·다른 어르신 정보가 섞이는 회귀 테스트를 둔다.

## 6. 운영 데이터 축적과 학습 권리

### 6.1 서비스 동의와 학습 동의 분리

일반 운영 음성은 처리에 필요한 동안만 임시 보유하고 삭제한다. **선택적 학습 참여를 명시적으로 허용한 대상의 허용된 구간만** 별도 학습 저장소로 복사할 수 있다. 미동의·철회가 기본 대화 서비스 이용을 막지 않는다. 녹음 수집 목적, 학습 종류, 항목, 기간, 제공/위탁, 거부·철회 방법을 구분한다. 담당자 편의나 가족의 서명만으로 성인 본인/대리 권한이 충족됐다고 간주하지 않는다.

가명정보 연구 활용 등 법적 경로도 존재하지만, 원음이 이름 삭제만으로 익명화되는 것은 아니다. 기억온은 초기에는 선택 동의 경로를 제품 정책으로 채택하고 다른 경로는 별도 적법성 검토 없이 적용하지 않는다. 이는 “모든 AI 학습에 동의가 법적으로 유일한 근거”라는 주장이 아니다. [개인정보위 AI 개인정보 정책방향(2023)](https://www.pipc.go.kr/np/cop/bbs/selectBoardArticle.do?bbsId=BS074&mCode=C020010000&nttId=9083)

### 6.2 Gemini 결과를 곧바로 학습 데이터로 쓰지 않음

Gemini API 추가 약관에는 서비스와 경쟁하는 모델 개발에 서비스 사용을 제한하는 조항이 있다. 또한 Paid Services의 공급자 제품 개선 미사용이 자체 모델 학습 권리나 국내 처리·무보관을 보장하지 않는다. **Gemini 출력·자동 전사·그 수정본의 재학습과 증류는 적용 계약 및 사용 목적의 허용 여부 확인 전 제외한다.** Vertex AI에 별도 계약이 적용되는 경우도 해당 계약을 별도로 확인한다. [Gemini API 약관, Use Restrictions / Paid Services](https://ai.google.dev/gemini-api/terms)

운영 기록과 학습 후보를 분리하고, 모델 출력에서 파생된 자료에는 그 출처를 표시한다. 독립 원음 수집·사람의 원음 전사·전문가가 독립 작성한 다음 발화·적법한 외부 데이터셋을 우선 검토한다. **사람이 수정했다는 이유만으로 계약 제한이 없어지는 것은 아니다.** Gemini가 참여한 세션 데이터의 사용 범위도 검토한다. 권리가 불명확하면 모델 결과를 보지 않고 별도로 수집·라벨링한 자료로 연구한다.

### 6.3 보유·접근·철회

원음·전사·라벨·개인 사전·백업·모델 체크포인트별로 목적과 보유기간을 지정한다. 기간 수치는 아직 정하지 않았으며 **목적별 기간과 자동 파기가 확정되기 전 학습 수집을 시작하지 않는다**. 서울의 private 저장소, 암호화, 최소 권한, 접근 감사, 외부 라벨러 계약, 제3자 목소리/가족 개인정보의 제외·적법성 확인을 포함한다. 원음은 공개 CDN이나 공개 학습 허브에 올리지 않는다.

철회 시 신규 수집과 다음 학습 배치를 즉시 제외하고 허용 범위에 따라 원음·라벨·파생 자료를 삭제한다. 배포 가중치에서 특정 개인 영향이 즉시 제거된다고 약속하지 않는다. 데이터셋–체크포인트 계보로 영향 범위를 찾아 격리·롤백·재학습 필요성을 결정하고 결과를 기록한다. 백업 복원 시 삭제 목록을 다시 적용한다.

서울 Supabase에 저장해도 해외 API 처리까지 국내가 되는 것은 아니다. 선택한 모델·제품·엔드포인트별 저장 및 처리 위치, 공급자 로그·캐시, 재이전과 DPA를 확인한다. 국내 처리까지 요구되는 기관은 확인되지 않은 해외 경로로 보내지 않고 국내 처리 대안을 사용한다. 리전 기능표만으로 특정 모델의 국내 추론 가능성을 단정하지 않는다. [Google 데이터 위치 문서](https://docs.cloud.google.com/gemini-enterprise-agent-platform/resources/data-residency)

## 7. 단계별 실행과 도입 게이트

| 단계 | 작업과 산출물 | 다음 단계 진입 조건 |
|---|---|---|
| A0 기준선·권리 | 현재 Live를 기준선으로 자동 진행·검증 Clova 출력 경로를 같은 한국어 음성으로 비교. 계약·데이터 흐름·대상 범위 확인 | 테스트 사용 권리, 지표·합격 기준·담당자 사전 확정 |
| A1 초기 서비스 | Live 자동 대화·예외 확인·프롬프트·지원 모드·개인 사전·문맥 안전·검증 Clova TTS 구현 | 출력 재생·오인식·모호 위험·장애 시나리오 통과, 현장 지원 가능 |
| A2 데이터 운영 | 선택 동의·독립 전사/대화 라벨·검수·기간별 파기·철회·계보 구축 | 권리와 라벨 품질 확인, 취약 하위군과 미등록 화자 평가셋 확보 |
| A3 Whisper 연구 | 미세조정하지 않은 기준 모델과 Whisper SFT/LoRA 및 다른 ASR 후보 비교 | 전체·하위군 인식/의미 성능, 무음 환각·긴급 의미 누락, 지연·비용 게이트 통과 |
| A4 대화 모델 연구 | 한국어 공개 가중치 LLM 선정 → 외부 도구로 SFT/LoRA → 지원 형식 변환 → Ollama 추론 검증 | 기준선 대비 대화 품질·안전·개인정보 누출·동시성 평가 통과 |
| A5 제한 전환 | ASR와 LLM을 독립적으로 shadow 평가 → 허용된 소규모 실제 전환 → 확대 | 운영 책임자 승인, 장애·품질 악화 시 즉시 이전 승인 경로로 복귀 |

Whisper 학습 목표는 **실제 들린 말을 보존하는 전사**다. 사투리 표준화, 문장 윤문, 인지능력 판정은 ASR 정답에 섞지 않는다. 한국어 표기·군말·불명확 구간 라벨 규약을 고정하고 무음·TV·겹침·짧은 맞장구도 포함한다. 합성 음성은 보조 자료이며 고령자 실발화 평가를 대신하지 않는다.

대화 모델 학습 목표는 지원 수준에 맞는 질문, 확인·공감·중단, 맥락 위험 처리와 구조화된 행동 선택이다. 공통 정책 모델에 **개인별 정보를 조회해 주입**하는 구조를 기본으로 한다. 개인마다 별도 LLM을 학습하는 방식은 데이터 부족·과적합·삭제·운영 부담 때문에 기본안에서 제외한다. 프롬프트+조회만으로 충분하면 파인튜닝하지 않는다. 전문가 선호 데이터가 확보된 뒤에만 추가 선호학습을 검토한다.

텍스트 LLM으로 전환하면 Gemini 오디오 직접 입력에서 이용 가능했던 억양·휴지 등의 정보가 줄어든다. 필요한 경우 측정된 음질·휴지·발화 길이 정보를 별도 관찰 신호로 전달하되 감정이나 인지를 단정하지 않는다. 전사 성능만 좋아져도 종단 대화가 나빠지면 전환하지 않는다. TTS는 STT/LLM 교체와 독립적으로 유지·평가한다.

Ollama는 우선 국내 개발·파일럿 추론 후보이며, 대규모 운영 적합성은 부하 측정 후 판단한다. GPU 서버·모델 레지스트리·큐·인증 게이트웨이·접근 감사가 별도로 필요하고 Ollama 포트를 인터넷에 직접 공개하지 않는다. Edge Functions에서 모델을 학습하거나 GPU 가중치를 로딩하지 않는다. 사용량 증가 시 동시 처리·메모리·지연에 맞는 추론 서버도 비교한다.

## 8. 평가 설계와 출시 조건

학습·검증·최종 테스트는 기본적으로 **화자 단위로 분리**하고 기관·녹음 환경 편중을 점검한다. 동일 세션의 청크나 합성 변형을 서로 다른 분할에 넣지 않는다. 미등록 화자 성능과 등록 화자의 미래 세션 개인화 성능은 별도로 보고한다. 최종 테스트셋을 프롬프트 수정이나 하이퍼파라미터 선택에 재사용하지 않는다.

| 평가 축 | 측정 | 합격 판단 |
|---|---|---|
| 발화 인식 | 한국어 CER/WER(정규화 규칙 고정), 핵심 의미·부정·이름 보존, 재확인율 | 같은 자료의 기준선 대비 개선과 표본 수·불확실성 함께 보고 |
| 취약 하위군 | 방언·발음 명료도·음량·기기·소음별 결과 | 평균 개선으로 특정 집단 악화를 숨기지 않음 |
| 허위 기록 | 무음/TV의 발화 생성, 화자 혼동, 원전사 덮어쓰기 | 필수 회귀셋의 기록 무결성 실패가 있으면 출시 차단 |
| 대화 적합성 | 이해 도움, 비유도성, 질문 부담, 교정/기억시험, 본인 중단 존중 | 담당자 블라인드 비교와 실제 이용자 수용성 평가 |
| 안전 | urgent 미탐, 불필요 urgent, clarify 해소, 담당자 알림량/응답시간 | 중요 시나리오 통과 + 하위군 재현율/정밀도·미탐 비용 평가 |
| 개인화 | 올바른 개인 의미 적용, 근거 없는 기억 생성, 기관 간 누출 | 타인 정보 노출·명백한 위험 무시는 필수 차단 사례 |
| 속도·운영 | 발화 종료→검증된 첫 음성 P50/P95, 인간 확인 대기 별도, 실패/재시도 | 기존 E2E 5초는 초기 목표, 실기기·동시성·예산에 맞춰 계약화 |
| 비용 | API/음성 길이 + GPU 유휴·피크 + 라벨링·검수·보관·운영 인건비 | 세션당 총비용과 감당 가능한 현장 확인 부담으로 판단 |

숫자 목표는 측정 결과가 아니다. 현장 기초자료 없이 데이터 몇 시간·인식률 몇 %·인지 향상을 보장하지 않는다. A0에서 각 하위군 표본과 합격/비열등 한계를 사전 합의하고, 작은 표본에서 오류 0건이어도 위험 0이라고 홍보하지 않는다. 안전·기록 무결성 실패, 권리 불명확, 철회/파기 실패는 성능 점수와 무관한 출시 차단 사유다.

## 9. 현재 구현과 남은 작업

- 확인됨: Live 오디오·전사·교정 경로, 단기 토큰/사용 자격 검사, core 안전·프롬프트, 세션/안전 이벤트 저장 구조.
- 신규 작업: Live 자동 턴·시작/회수·서버 응답 검증·Clova TTS 배선·실사용 원가 계측, 지원 모드·개인 의미 저장/승인, 문맥 위험 검토와 해결 이력, 학습 동의·저장소·계보·파기, 독립 평가셋.
- 아직 확인하지 않음: 실 API 계정의 모델 제공 상태·계약·국내 처리 범위, 한국어 대상 품질·비용·동시성, 학습용 데이터 권리와 확보량, Whisper/공개 LLM 학습 및 Ollama 배포 결과.
- 구현 착수 순서: A0 → A1. A2는 동의·권리·보유기간 확정 후 시작하며 A3/A4는 데이터와 기준선이 준비된 뒤 각각 판단한다. 자체 모델 전환 완료 전에도 초기 서비스의 네 가지 대응 정책은 필수다.
