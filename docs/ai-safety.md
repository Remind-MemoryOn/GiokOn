## 0. 설계 원칙 (근거)

| # | 원칙 | 근거 | 구현 |
|---|---|---|---|
| 1 | **생명 우선** — 위기는 AI가 상담하지 않는다 | 자살·응급·학대는 사람 개입 사안. 과탐>미탐 | 위기 감지 → 안전응답 + 즉시 에스컬레이션 + 세션 마무리 권고 |
| 2 | **검증(validation) 우선** — 상실·애도는 회피하지 않는다 | 회상 대화에서 부정 기억 통합은 치료적(생애회고). 강제 전환은 무시로 느껴짐 | 공감 인정 + **어르신이 선택**(계속/전환). 3회 연속 침잠 시에만 부드럽게 이동 |
| 3 | **교정 금지** — 사실 오류·반복을 지적하지 않는다 | 치매 돌봄 금기(validation therapy). 직면은 고통·혼란 유발 | 출력 가드레일이 "아까 말씀하셨잖아요"·기억 시험류 차단 |
| 4 | **자기결정 존중** | 어르신은 대화의 주체 | 중단·거부 의사 즉시 존중(마무리/물러남) |
| 5 | **비의료** | 서비스 포지셔닝 락다운 | 출력 가드레일이 진단·약·치료 표현 차단 |
| 6 | **상태 신호 기반 진행** — 고정 카운터 없음 | "동일 주제 N회 금지" 같은 임의 규칙 배제(사용자 지시). 전환은 어르신 상태가 결정 | 관여도(rich/normal/low/silent)·감정 신호·어르신이 꺼낸 주제로만 전환 |

| 사람 확인 | AI 산출물(일지 초안·보호자 문장)은 사람이 확정·승인하기 전엔 공식 기록도, 보호자에게 가는 글도 아니다 | DB 트리거(서비스 계정 확정 불가) · 워커(확인 대기까지만) · UI(권한자만 확정 버튼) **세 층을 각각 테스트** |

## 1. 상황 분류·대응 (M12.1·12.2 — 구현: `core/safety.ts`, `core/ai.ts`)

> ⚠️ 분류(`safety.ts`)는 유효하다. 아래 "대응" 열의 문장 생성과 "대화 진행(전환) 규칙"은 `ai.ts` 규칙 기반 대화의 것이라 **중계 경로에서는 쓰이지 않고**, 파일럿에서 대화 정책 지시로 옮긴다. 중계의 실제 대응은 §0-1.

어르신 발화를 정규화(STT 띄어쓰기·문장부호 변이 흡수) 후 **8가지 상황**으로 분류한다.
우선순위: 위기 > 중단요청 > 급성고통 > 거부 > 혼란 > 애도 > 침묵 > 일반.

| 상황 | 감지(구 단위 사전 — 단일 글자 금지, 오탐 억제) | 대응 |
|---|---|---|
| **crisis: 자살·자해** | 죽고싶·자살·약을모아·따라가고싶·"내가 없어야"(수동적 소망·짐 인식) 등 | 안전응답(따뜻한 지지+"선생님 불러드릴게요") + **에스컬레이션(☎109 안내)** + 마무리 권고 |
| **crisis: 응급** | 호흡곤란·흉부 압박·뇌졸중 신호(한쪽 마비·발음)·낙상 후 기립 불가 등 | 안전응답 + **에스컬레이션(☎119)** + 즉시 마무리 |
| **crisis: 학대** | 현재진행 신고 구문(자꾸 때려·밥을 안 줘·통장 뺏어·가둬 놓) — 과거 회상과 구분 | 지지·비난 회피 응답 + **에스컬레이션(☎1577-1389/112)** |
| **distress: 급성 고통** | 못살겠·견딜수없·짐만 되(노인 자살 선행 신호) | 지지 응답 + 보호자 관찰 알림(watch). 2회 연속 시 부드러운 전환, 3회 시 휴식 제안 |
| **rest_request: 중단·휴식** | 그만하고싶·피곤해·쉬고싶 | **즉시 존중** — 따뜻한 마무리. 고통 신호 동반 시 관찰 알림 유지 |
| **refusal: 거부·짜증** | 듣기싫·왜자꾸물어 | 사과+물러남(질문 강요 없음). 반복 시 마무리 |
| **confusion: 지남력 혼란** | 여기가어디·누구세요 | 교정 없이 재소개(AI 정체 고지 겸함)+안심+쉬운 재질문 |
| **grief: 애도·그리움·외로움** | 사별·먼저 갔·그리워·외로워 | 공감 인정+선택권(§0-2). "보고 싶어 죽겠네" 같은 관용구는 위기로 오탐하지 않음 |
| **silence: 침묵** | 무발화 | 단계적: 재청 → 쉬운 주제 → 휴식 제안 |

**오탐 방지 검증됨**: 죽(음식)·예방주사 맞았어·병원 정기검진·과거 회상("옛날엔 선생님이 때렸지")은 일반 대화로 처리.
**부정 문맥**("죽고 싶다는 생각은 안 해요")은 위기로 유지 — 자살 언급 자체가 확인 대상, 판단은 사람이.

### 대화 진행(전환) 규칙 — 고정 카운터 없음
- **rich**(서사 표지·긴 이야기): 같은 주제 계속 — 회상이 작동하는 순간을 끊지 않는다.
- **low**(단답·맞장구) 1회: 같은 주제를 더 쉽게(스캐폴딩). **연속**: 다른 쉬운 주제로.
- **어르신이 먼저 꺼낸 주제**: 즉시 따라간다(person-centered).
- **힘들어했던 주제**(애도·고통 반응이 있던 주제)로는 되돌아가지 않는다.
- ~~목업 한정: 질문 풀 소진 시 다리 문장과 함께 이동(같은 질문의 기계적 반복 금지 — 실 LLM은 프롬프트 규칙).~~ (목업·규칙 기반 대화 삭제)

### 출력 가드레일 (모든 AI 발화, mock/실 LLM 공통 후단)
의학 단정(치매입니다·약을 끊으세요) · **교정/직면/기억시험**(아까 말씀하셨잖아요·기억 안 나세요?) ·
유해/모욕 → 차단하고 안전한 중립 발화로 대체. 위기 안전응답(신뢰 템플릿)은 검열 대상에서 제외.

## 2. 에스컬레이션 영속화 (M12.1 — 구현: `safety_events` 테이블 + `data/hooks/safety.ts`)
- 위기(crisis)·관찰(watch) 이벤트를 저장: 수준·분류·매칭어·발화 발췌(120자, RLS 보호)·알림 문구·확인(acknowledge) 이력.
- **RLS 의도적 예외**: 같은 기관 구성원 **전체** 조회 — 담당자 부재(교대) 시에도 위기가 보여야 함(어르신 안전 > 접근 최소화). 타 기관 차단·임의 삭제 불가·감사로그 적재는 회귀 테스트로 검증.
- 웹 대화 화면: 위기·관찰 알림 배너(`role="alert"`) + 안전응답 재생 후 자연스러운 세션 마무리.
- ⚠️ 2026-09-23: 지금 `safety_events` 는 **세션 종료 시 일괄 기록**된다 — 실시간 알림이 불가능하다. 파일럿에서 중계가 감지 즉시 기록한다(계획 C3). 위기 배너(전화번호)는 어르신 화면에서 빼서 요양보호사 모드·감독 화면으로 옮긴다(M3·W2).

## 3. 실 LLM 안전 (Phase M — 구현: `core/prompt.ts`)
- **3중 방어**: ① LLM 호출 **전** 결정론 위기 감지(비용·지연 없이 확실한 처리) → ② 시스템 프롬프트(돌봄 원칙·위기 프로토콜 인코딩) → ③ 호출 **후** 출력 가드레일. 모델의 safety.risk 출력과 결정론 감지는 **OR 결합**(하나라도 위기면 에스컬레이션).

  → 2026-09-23 **삭제 대상** → ✅ 2026-09-24 삭제(직접 모드 전용 — Live 는 Structured Outputs 를 보장하지 않는다). 중계 경로에는 모델의 `safety.risk` 출력이 없으므로

## 5. 검수·평가 (M12.4 — 후속)
- **human-in-the-loop**: 대화 로그 샘플 검수 프로세스(부적절·위기 놓침 점검). safety_events 확인(acknowledge) 흐름이 1차 검수 채널.
- **안전 평가셋·레드팀**: 위기·유해·탈옥 프롬프트 테스트셋 회귀 평가. 모델 교체 시 한국어 품질·안전·지연·비용 재평가. 결정론 레이어의 사전(lexicon)은 파일럿 로그 기반으로 지속 보강.
- 사전 기반 감지의 한계(반어·완곡어)는 실 LLM 의미 감지(§3 OR 결합)로 보완.

> OR 결합은 현재 보수적 정책이며 문맥 오탐 해결을 보장하지 않는다. 새 정책의 분류/행동 분리와 완료 조건은 §7을 따른다.

## 7. 신규 정책 — 문맥 확인과 개인별 대화 지원(미구현)

- 부정 감정, 음성 인식 불확실성, 현재 긴급 위험을 별도로 판단한다. 주체·인용·시제·부정·관용 표현과 직전 대화를 확인한다. 일반 슬픔은 공감과 선택권으로 대응한다.
- 행동을 계속/확인/관찰/긴급/중단으로 구분하는 계약을 설계한다. 명확한 현재 위험은 지연 없이 담당자에게 연결한다. 모호한 위험은 짧은 확인·담당자 검토가 필요하며 미해소·무응답을 안전으로 종결하지 않는다.
- 모델이 안전하다고 해도 명백한 긴급 신호를 무시하지 않는다. 반대로 모든 키워드 후보를 곧바로 긴급 판정하는 기존 OR 규칙의 완화는 독립 안전 평가와 책임자 승인 후 적용한다. 현재 DB enum을 문서만으로 확장하지 않는다.
- 알림 확인과 위험 해결을 구분한다. 오탐 정정·확인 근거·담당자·시각을 원 이벤트에 추가하며 삭제하지 않는다. 학대 의심 시 지목된 제공자 외의 책임자 경로, 담당자 부재·네트워크 실패 대응을 검증한다.
- 개인 의미 사전은 근거·승인·유효 범위가 있는 항목만 사용한다. 관용 표현을 안전 예외 목록으로 고정하지 않으며 다른 어르신의 정보를 가져오지 않는다.
- 인지능력·동의능력을 음성으로 판정하지 않는다. 요양보호사가 정한 지원 방식에 세션 반응을 반영하고 변경 이유를 남긴다. 낮은 음질·청력·피로·맞장구를 인지 저하와 혼동하지 않는다.
- 검증 텍스트만 TTS로 재생한다. Live 출력 전사가 안전하다는 이유로 원음 의미까지 검증됐다고 보지 않는다. 교정 후에는 교정 전 질문/음성 결과를 폐기한다.
- 출시 전 필수 사례: 관용/부정/과거 인용, 현재 자해·응급·학대, 반대 의미로 전사된 발화, 침묵·TV, 담당자 미응답. 미탐·오탐·재확인 부담과 실제 알림 대응을 함께 평가한다. 상세 실행·근거는 [전환 계획 §4·§8](plans/voice-ai-personalization.md).

## 2026-09-12 사업 기획 반영 사항 (당시 기록)

담당자 매 턴 확인이 없어지는 목표에 맞춰 어르신 재확인·음성 중단·긴 침묵·기기 오류·알림 미응답을 검증한다. 원전사/해석/당일 관찰은 구분한다. 출력 전사 누락·불일치·차단 시 Gemini 원본 오디오를 재생하지 않는다. 담당자 개입 없는 운영의 안전성은 미검증이다. 기존 가드를 먼저 제거하지 않는다.

## 2026-09-23 기획 변경 반영 사항

**위 제약은 전부 유효하다.** 특히 *"Gemini 원본 오디오를 재생하지 않는다"* 와
*"기존 가드를 먼저 제거하지 않는다"* 는 새 계획의 설계 근거다([`pilot-development-plan.md`](plans/pilot-development-plan.md) §9·§11).
- 규칙 기반 대화(`ai.ts`)를 삭제해도 **안전 계층**(`assessUtterance`·`screenAiUtterance`·
  `buildCaregiverAlert`·`buildSafetyEventDraft`)은 유지한다.
- 기획서 6-3 의 "AI 판단으로 일시정지"는 **약화로 읽지 않는다** — 현재 동작(결정론 감지 시 즉시 연결 종료)이
