# BB-01 수정·재검증 — 2026-10-24

**로그인 뒤 원래 감독 화면으로 돌아가지 않던 결함을 수정했다.** 로컬 코드·검증 완료이며 main 반영·운영 배포·실계정 OAuth/푸시 확인은 별도다. 앞선 블랙박스·유스케이스 보고서와 실패 증거는 수정 전 기록으로 보존한다.

보관 텍스트 로그는 줄 끝 공백과 개행 형식만 정규화했다. 원본 로그는 로컬 `.tmp`에 남겼다.

## 변경과 범위

- 원인: `CaregiverGuard`·`GuardianGuard`가 원래 주소를 버리고 `/login`으로 이동했다. 로그인 화면의 이메일 성공·네이버 콜백·이미 세션이 있는 경우도 항상 역할별 첫 화면으로 보냈다.
- 수정: 보호 화면의 경로·검색 조건·앵커를 `/login?returnTo=…`에 보존하고, 모든 로그인 성공 경로가 같은 복귀 판정을 사용한다. 로그인 화면 새로고침과 소셜 로그인 콜백에도 복귀 정보를 전달한다. 문의 화면의 기존 `state.from`도 지원한다.
- 경계: 온보딩·기관 승인 대기를 우선한다. 역할이 다른 보호 영역, 외부/프로토콜 상대 주소, 역슬래시·제어문자, 로그인 반복 경로·유사 접두사는 역할별 첫 화면으로 돌린다. 공개 문의 경로는 로그인 후 복귀할 수 있다.
- 수정 제품 파일: [App.tsx](../../apps/web/src/App.tsx), [auth/routes.ts](../../apps/web/src/auth/routes.ts), [LoginPage.tsx](../../apps/web/src/pages/public/LoginPage.tsx). 화면 치수·카피·법률 문서·DB·중계·앱은 변경하지 않았다. 의존성 추가 없음.
- 새 브라우저 회귀 `test:login-return`을 CI의 인증 격리 검사 다음에 추가했다. 소셜 검증은 요청의 콜백 주소와 합성 네이버 콜백 수신까지다. 실제 제공자 인증·운영 리다이렉트 허용 목록·푸시 수신은 검증하지 않았다.

```cmd
pnpm -F @giokon/web test:login-return
pnpm -F @giokon/web exec node scripts/blackbox-flow-smoke.mjs
pnpm -F @giokon/web exec node scripts/usecase-flow-smoke.mjs
```

수정 전/가드 제거의 실패 재현은 각각 다음 명령으로 실행한다. 두 명령의 종료 코드 1은 결함·가드 제거를 검출했다는 뜻이다.

```cmd
pnpm -F @giokon/web test:login-return --baseline
pnpm -F @giokon/web test:login-return --unguarded-return
```

모든 새 브라우저 시험은 `envDir:false`와 합성 공개 설정으로 빌드하며 외부 인증 응답을 가로챈다. 실제 계정·운영 DB·배포에는 쓰지 않는다. DB·중계·앱 제품 코드를 수정하지 않아 앞선 DB 17스위트 및 유스케이스 4개 결과는 이전 기록을 참조하고 이번에 재실행했다고 집계하지 않는다.
