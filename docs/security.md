# security.md — 보안·데이터 인프라 (엔터프라이즈급)

> 목표: 「개인정보 안전성 확보조치 기준」 전 항목 충족 + 저장/전송 암호화·최소권한 RBAC·감사로그·
> 취약점관리·침투테스트. ISMS-P(자율·B2G 가점)·CSAP(공공조달) 로드맵. 관련: PLAN §2′ M10·M14,
> `docs/compliance.md`. 인프라 내용은 이 문서 끝 "인프라" 절.

## 1. 데이터 국내화 (M10.1)
- **Supabase 서울(ap-northeast-2) 신규 프로젝트**로 이전(도쿄 `GiokOn` 폐기). 스키마·RLS·데이터 이전 → 앱 재배선(`packages/data` env) → 도쿄 폐기.
- 국외로 나가는 provider(LLM/STT/TTS)는 국외이전 동의·처리방침·위수탁계약으로 관리.

## 2. 「안전성 확보조치 기준」 매핑 (규모 무관 의무)
- **암호화**: 비밀번호·고유식별정보 저장 암호화(Supabase Auth 기본) + **민감정보(건강·음성) 저장 암호화**(pgcrypto/앱레벨 또는 KMS 봉투암호화) + 전송 TLS 강제.
- **접근통제**: 취급자 **업무상 최소권한 차등 부여**(RBAC), 인증·접근권한 관리. → **RLS(조직+역할) 는 이 요건의 좋은 출발점**(§3).
- **접속기록(audit)**: 접속일시·처리내역 저장·정기점검. 원칙 1년 이상; **5만명 이상 정보주체 또는 민감·고유식별정보 처리 시 2년 이상** → 보수적으로 **2년**. → `audit_log` 테이블/트리거(§4).
- **인증 강화**: MFA(옵션), 세션 만료·비밀번호 정책.
- 출처: [안전성 확보조치 기준(국가법령정보센터)](https://www.law.go.kr/admRulLsInfoP.do?chrClsCd=010202&admRulSeq=2100000229672)

## 3. RLS · RBAC 강화 (M10.3 · M14)
- 전 테이블 RLS를 **"본인 + 같은 조직(역할 범위)"** 로 확장(멀티테넌시): `organizations`, `users.org_id`, 역할(`org_admin`/`caregiver`/`guardian`).
  - 예: 요양보호사=본인 담당 어르신, 기관관리자=소속 조직 전체, 보호자=동의된 대상만.

  ⚠️ 위 예시는 2026-07 설계다. 역할 → 범위는 두 번 바뀌었다(아래 표). 파일럿 목표의 SoT 는
  [`pilot-development-plan.md`](plans/pilot-development-plan.md) §4-A · §5 D1~D4 다.

  | 역할 | 현재 (`20260722100000`) | 파일럿 목표 (2026-09-23) |
  |---|---|---|
  | 요양보호사 `caregiver` | 같은 기관 + **배정된(active) 어르신만** | 같은 기관 **전체**(교대근무) — 삭제만 배정 기준 유지 |
  | 사회복지사 `social_worker` | (없음) | 같은 기관 전체 + 기본 위임(일지 확정·공개/철회·보호자 연결 승인) |
  | 센터장 `center_director` | (없음) | 같은 기관 전체 + 기본 위임 + 권한 매트릭스 편집·역할 지정·직원 합류 승인 |
  | 기관 관리자 `org_admin` | 같은 기관 전체 | 센터장과 같음(기관을 만든 계정) |
  | 보호자 `guardian` | 연결 승인된 어르신의 **공개된 항목만** | **변경 없음** |
  | 합류 대기 직원 | (경로 없음 — 요양보호사마다 새 기관) | `users.org_id` NULL → **0건** |
  | 서비스 계정 워커 | — | 일지 초안을 확인 대기까지만. **확정 불가**(DB 트리거) |
- **service key 격리**(클라이언트 미노출), Edge Function은 호출자 JWT 검증 후 처리.
- **pgTAP RLS 회귀 테스트**: 타 조직·타 사용자·타 역할 접근이 0건임을 자동 검증(CI 게이트).
  실제 게이트는 `bash supabase/tests/run-rls-regression.sh`(PG16 실기동 + 전 마이그레이션 적용). 파일럿 권한 전환은 이 회귀를 통과해야 완료다(파일럿 계획 §12).

## 4. 감사로그 (audit_log)
- 스키마(예): `id, actor_id, org_id, action, entity, entity_id, ip, user_agent, at`. 민감 리소스 접근/변경/삭제·동의·삭제요청 기록.
- 2년 보관, 변조 방지(append-only), 정기 점검 리포트.

## 5. 시크릿·키 관리 (M10.4)
- Supabase secrets / GitHub Secrets / (옵션) Vault. provider 키 서버사이드 전용, 키 로테이션, 최소권한 토큰. `.env` 커밋 금지(세션훅으로 주입).

## 6. 취약점·사고 대응 (M10.5)
- CI: 의존성 스캔(SCA), SAST, **secret-scan**. 정기 **침투테스트**(외부 1회+주기), 취약점 관리·패치 SLA.
- 보안사고 대응(IR) 플레이북(탐지·격리·통지·복구), 개인정보 유출 통지 절차(법정 기한).

## 7. 인증 로드맵 (M10.6) — 심사는 외부
- **ISMS/ISMS-P**: 의무대상(매출 100억/이용자 100만 등)은 통상 미해당이나 **B2G 신뢰·가점**으로 자율 취득 로드맵.
- **CSAP**: 공공 클라우드 조달 시 필수 — 국내 리전·물리요건 전제.
- 출처: [ISMS-P 대상(KISA)](https://isms.kisa.or.kr/main/ispims/target/)

## 8. 검증
- 민감 컬럼 암호화·`audit_log` 적재 확인, RLS/RBAC pgTAP 회귀 0건, SCA/SAST/secret-scan CI 통과, 침투테스트 리포트, 키/시크릿 노출 스캔 0.

## 2026-09-12 사업 기획 반영 사항 (당시 기록)

Live 자동 진행과 Clova 검증 출력 변경에서도 세션·기관·배정·동의·사용 제한은 서버가 집행해야 한다. 기존 R010 직접 공급자 연결 수명 통제의 미해결 범위를 유지한다. 학습 원음/라벨과 운영 자료는 권한을 분리하고, 사용량 이벤트에 개인 발화/원음을 남기지 않는다. 신규 공유·구독·계측 테이블은 기관 격리·재시도 멱등성·철회 접근을 검증한다.

## 2026-09-23 기획 변경 반영 사항

**위 제약은 유효하다.** 추가로 **권한 모델이 배정 격리 → 기관 단위 + 역할 기반으로 바뀐다**
(교대근무라 오후 담당자가 오전 세션 기록을 봐야 한다 — [`pilot-development-plan.md`](plans/pilot-development-plan.md) §4-A).
이는 개인정보 최소수집과 충돌하므로 `product_events.profile_viewed` 로 **열람 이력을 남겨 보완**한다.
보호자 격리는 **그대로** 유지한다. 위임 가능 capability 는 3개뿐이며 안전 가드는 설정으로 끌 수 없어야 한다.
푸시 본문에 **어르신 성함·발화를 넣지 않는다**(잠금화면 노출).

코드 대조로 추가된 보안 항목(2026-09-24):
- **`live-token` 중계 전용화**(✅ 2026-10-02 코드 — 공유 시크릿 `VOICE_RELAY_SECRET`(32자 이상) → 중계가 `x-relay-secret` 헤더로 보냄 · `live-token` 은 JWT·DB 한도 검사 **전에** 확인해 없거나 틀리면 403(한도 소모 없음) · 시크릿 미설정·짧으면 발급 안 함(500) · ⏳ 배포) — 구현 전에는 중계도 사용자 JWT 로 호출해 서버가 앱 직접 호출과 구분하지 못한다. 앱 코드를 지워도
  구버전 앱·JWT 소지자는 출력 검열을 건너뛴다 → 중계만 가진 자격을 추가로 요구하고 없으면 403(파일럿 계획 C4). 이것이 R010 의
  남은 범위(직접 공급자 연결)를 닫는다.
- **역할 변경 경로** — `users.role` 3중 잠금(`20260908000000`)은 유지한다. 새 역할은 `set_member_role` RPC 로만 부여하고,
  자기 자신·보호자↔돌봄팀 전환·마지막 관리자 강등을 막는다. **셀프 승격 차단 원칙이 그대로 이어져야 한다.**
- **직원 합류 승인 = 기관 전체 열람 부여**가 되므로 승인자는 `org_admin`·`center_director` 로 좁히고, 승인 전 `users.org_id` 를 NULL 로
  둬 기존 "org_id 없으면 0건" 불변식에 태운다. 초대 코드는 기존 CSPRNG 생성기(`app.generate_invite_code()`) 재사용.

### 인프라 1. 리전·데이터 위치
- **Supabase 서울(ap-northeast-2)** 단일 소스(데이터 국내 보관). 정적 자산은 CDN.

### 인프라 2. 데이터/쿼리 확장 (M11.1)
- 인덱스 점검(소유·조회 축), **N+1 제거**(대시보드 카운트는 집계 훅), **커넥션 풀링(Supavisor)** — 서버리스/피크 대비.
- 읽기 캐싱: TanStack Query `staleTime` + CDN 정적. 무거운 집계는 뷰/RPC.

### 인프라 3. 음성 파이프라인 부하 (M11.2)
- Edge Function 동시성·타임아웃·재시도·백프레셔. **레이트리밋/쿼터**(세션·사용자·기관 단위) — 남용·비용 방지.
- 원음·학습 자료는 private 저장소이며 공개 CDN에 노출하지 않는다. 운영 원음은 처리 후 삭제, TTS는 임시 재생 수명, 선택 학습 원음은 승인된 목적별 보유기간을 각각 적용한다.

### 인프라 4. 부하테스트·용량·SLO (M11.3)
- **k6 시나리오**: 로그인·프로필 CRUD·연대기 CRUD·세션 응답(STT→LLM→TTS). 목표 동시성·RPS 정의.
- **성능 SLO(부하 하)**: STT ≤ 3s, TTS 첫재생 ≤ 2s, STT+LLM+TTS ≤ 5s, 프로필 저장 ≤ 2s, 조회 P95 목표.
- 용량계획·오토스케일(관리형), 콜드스타트 완화(웜업).

### 인프라 5. 백업·DR (M11.4)
- **PITR**(Point-in-Time Recovery) + 정기 백업, **복구 리허설**(주기적). 장애 등급·**RTO/RPO** 정의. 다중 AZ(관리형).

### 인프라 6. 릴리스 안전 (M11.5)
- **스테이징 환경**(프로덕션 미러), 카나리/피처 플래그, **무중단 DB 마이그레이션**(확장→백필→수축), 롤백 절차.

### 인프라 7. 관측성·비용 (M11.6)
- 관측성: Sentry(에러), 구조화 로깅, 헬스체크, 지연·오류율·비용 대시보드·알림.
- **비용 가드레일**: AI/STT/TTS 사용량 상한·알림·서킷브레이커(예산 초과 시 저하/차단).

### 인프라 8. 검증
- k6 목표 부하에서 SLO 충족, 백업 복구 리허설 성공, 스테이징→프로덕션 무중단 배포·롤백 검증, 관측성 대시보드·알림 동작.

### 인프라 9. 음성 AI 단계적 운영(2026-09-11, 신규 계획)

- [음성 AI 전환 계획](plans/voice-ai-personalization.md) A0~A5를 따른다. 초기 Gemini Live 입력·대화와 검증 텍스트의 Gemini TTS 출력을 사용한다. 서버가 매 전송·연결 수명을 통제하는 중계 환경을 유지하며 Edge Functions가 긴 연결을 감당한다고 전제하지 않는다. 타임아웃·재시도·취소·턴 멱등성과 누적 청구 토큰을 검증한다.
- Whisper 학습과 공개 LLM SFT/LoRA는 별도 국내 GPU 작업이다. Ollama는 학습 후 추론 후보이며 인증 게이트웨이·큐·모델 버전·동시성·GPU 메모리·헬스체크·관측성을 갖춘 뒤 파일럿에 사용한다. 포트를 공개하지 않고 서비스 비밀값과 개인 전사는 로그에서 제외한다.
- 국내 DB 위치와 해외 모델 처리 위치는 별도로 검증한다. 데이터셋·체크포인트의 국내 보관, 동의 철회 계보와 백업 복원 후 삭제 재적용을 포함한다.
- Shadow 평가는 허용된 자료만 사용하고 이용자 응답에 영향을 주지 않는다. ASR/LLM을 독립적으로 제한 전환하며 품질·안전·지연 악화 시 승인된 이전 모델로 복귀한다. 대체 경로의 처리 국가·동의도 충족해야 한다.
- 기존 5초 E2E는 초기 목표다. 발화 종료→검증된 첫 음성 P50/P95와 인간 확인 대기를 분리하고, API 비용뿐 아니라 GPU 유휴/피크·검수·라벨링·보관·운영 인건비를 포함한다. 필수 안전 검증을 지연 절감 목적으로 생략하지 않는다.

| 푸시 | Expo Push — EAS 프로젝트 · FCM/APNs 자격증명(EAS 관리) · `expo-notifications` 포함 **재빌드** | 신규. Expo 는 국외 처리자 |
| Realtime | `sessions`·`session_interventions`·`program_journals` publication · 감독 화면 두 브라우저 2초 반영 | publication 추가 + 클라이언트 3곳 등록 |
| 동시성 | 기기 2~4대 = Gemini Live 동시 연결 2~4 · `live-token` 한도(사용자 분당 3 · 일 20 · 기관 일 200) | ⚠️ 요양보호사 1명이 여러 기기를 시작하면 **사용자 한도**에 먼저 걸릴 수 있다 — 파일럿 전 한도 재확인 |
| 비용 | Gemini Live 동시 세션 한도·요금(기획 §8 개발 확인 사항) · CLOVA 문자 수 | 미확인 |

⚠️ `live-token` 한도는 **토큰을 받는 사용자 기준**이다. 파일럿에서 요양보호사 1명이 기기 여러 대의 세션을 자기 계정으로
시작하면 사용자 분당 3회·일 20회에 먼저 닿는다(`app.live_token_limits` 기본값). 기기별 계정을 쓸지, 한도를 조정할지는
파일럿 운영 방식에 따라 정한다.
